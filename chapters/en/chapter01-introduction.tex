\section{Definition and Functions of Operating Systems}
\label{sec:os-basics}

An operating system is system software that manages computer hardware resources and provides common services for application programs. The operating system acts as an intermediary between users and computer hardware.

\subsection{Dual Role of Operating Systems}

Operating systems have two main roles:

\begin{enumerate}
    \item \textbf{Resource Manager} --- Manages and allocates system resources (CPU, memory, disk, I/O devices) efficiently and fairly among various running programs.

    \item \textbf{Extended Machine} --- Provides abstraction from complex hardware, offering a more user-friendly interface for programmers and users.
\end{enumerate}

\begin{notebox}
Without an operating system, every program would need its own driver for each piece of hardware, which would be very inefficient and difficult to maintain.
\end{notebox}

\subsection{Main Functions of Operating Systems}

Modern operating systems have five main functions:

\subsubsection{Process Management}

The operating system is responsible for:
\begin{itemize}
    \item \textbf{Process scheduling} --- Determining which process gets CPU time
    \item \textbf{Process creation and termination} --- Creating and ending processes
    \item \textbf{Process synchronization} --- Coordinating multiple processes
    \item \textbf{Inter-process communication (IPC)} --- Facilitating communication between processes
\end{itemize}

Implementation examples:
\begin{itemize}
    \item \textbf{Windows}: Task Manager displays running processes and resource usage
    \item \textbf{Linux}: Commands \cmd{ps}, \cmd{top}, and \cmd{htop} for monitoring processes
    \item \textbf{macOS}: Activity Monitor for managing processes
\end{itemize}

\subsubsection{Memory Management}

Memory management functions include:
\begin{itemize}
    \item \textbf{Memory allocation} --- Allocating memory to processes that need it
    \item \textbf{Virtual memory} --- Using disk as an extension of RAM
    \item \textbf{Memory protection} --- Preventing one process from accessing another process's memory
    \item \textbf{Paging and swapping} --- Techniques for optimizing memory usage
\end{itemize}

\begin{examplebox}[Virtual Memory]
When RAM is full, the operating system moves some data to disk (swap space in Linux, pagefile in Windows) so applications can continue running, albeit with slower performance.
\end{examplebox}

\subsubsection{File Management}

The operating system provides:
\begin{itemize}
    \item \textbf{File system organization} --- Hierarchical structure (directories, subdirectories)
    \item \textbf{File operations} --- Creating, reading, writing, deleting files
    \item \textbf{Access control} --- Permissions for security
    \item \textbf{Mounting file systems} --- Integrating storage devices into the system
\end{itemize}

File system examples:
\begin{itemize}
    \item Windows: NTFS (New Technology File System)
    \item macOS: APFS (Apple File System)
    \item Linux: ext4, XFS, Btrfs
\end{itemize}

\subsubsection{I/O Management}

Input/Output management includes:
\begin{itemize}
    \item \textbf{Device drivers} --- Software for communicating with hardware
    \item \textbf{Buffering} --- Temporary storage for smooth I/O operations
    \item \textbf{Interrupt handling} --- Responding to signals from hardware
    \item \textbf{Spooling} --- Queuing for devices like printers
\end{itemize}

\subsubsection{Security and Protection}

Security aspects include:
\begin{itemize}
    \item \textbf{Authentication} --- User identity verification (password, biometrics)
    \item \textbf{Authorization} --- Access control to resources based on permissions
    \item \textbf{Encryption} --- Data protection (BitLocker in Windows, FileVault in macOS)
    \item \textbf{Auditing} --- Recording system activities for security monitoring
\end{itemize}

\section{Types and Categories of Operating Systems}
\label{sec:os-categories}

Operating systems can be categorized based on various criteria:

\subsection{By Platform}

\begin{description}
    \item[Desktop OS] Designed for personal computers with user-friendly interfaces. Examples: Windows 10/11, macOS, Ubuntu Desktop, Linux Mint.

    \item[Server OS] Optimized for running services and serving many clients. Usually without GUI or with minimal GUI. Examples: Windows Server, Ubuntu Server, Red Hat Enterprise Linux, FreeBSD.

\section{Kernel Architecture of Operating Systems}
\label{sec:kernel-architecture}

The kernel is the core of an operating system that has full control over the entire system. The kernel provides abstraction between hardware and software.

\subsection{What is a Kernel?}

The \textbf{kernel} is a program that is always running (resident) in memory and has exclusive access to hardware. The kernel is responsible for:

\begin{itemize}
    \item Low-level process management
    \item Memory management
    \item Device drivers
    \item System calls
    \item Interrupt handling
\end{itemize}

\subsection{Kernel Space vs User Space}

Modern operating systems separate memory into two areas:

\begin{description}
    \item[Kernel Space (Ring 0)] Memory area with the highest privilege. Only kernel code runs here. Full access to all hardware and memory.

    \item[User Space (Ring 3)] Memory area for user applications. Limited access to hardware. Must go through system calls to access kernel services.
\end{description}

\end{notebox}

\subsection{Types of Kernel Architecture}

\subsubsection{Monolithic Kernel}

\textbf{Characteristics:}
\begin{itemize}
    \item All services (file system, device drivers, memory management) run in kernel space
    \item Single large binary
    \item Direct function calls between components (fast)
\end{itemize}

\textbf{Advantages:}
\begin{itemize}
    \item \textbf{High performance} --- No overhead for context switching
    \item \textbf{Efficient communication} --- Function calls faster than IPC
    \item \textbf{Simpler design} --- Everything in one address space
\end{itemize}

\textbf{Disadvantages:}
\begin{itemize}
    \item \textbf{Reliability} --- Bug in one driver can crash the entire system
    \item \textbf{Security} --- Larger attack surface
    \item \textbf{Maintainability} --- Difficult to isolate and debug
\end{itemize}

\textbf{Examples:} Linux, traditional Unix, BSD

\subsubsection{Microkernel}

\textbf{Characteristics:}
\begin{itemize}
    \item Minimal kernel with only essential services (IPC, basic scheduling, low-level memory)
    \item Most services (file systems, drivers, network stack) in user space
    \item Message passing for inter-component communication
\end{itemize}

\textbf{Advantages:}
\begin{itemize}
    \item \textbf{Reliability} --- Service crashes don't affect the kernel
    \item \textbf{Security} --- Smaller attack surface, better isolation
    \item \textbf{Modular} --- Easy to add/remove services
    \item \textbf{Good for real-time} --- Predictable behavior
\end{itemize}

\textbf{Disadvantages:}
\begin{itemize}
    \item \textbf{Performance overhead} --- Context switches and IPC are slower
    \item \textbf{Complexity} --- Message passing adds complexity
\end{itemize}

\textbf{Examples:} MINIX 3, QNX, seL4, L4 family

\subsubsection{Hybrid Kernel}

\textbf{Characteristics:}
\begin{itemize}
    \item Combines ideas from monolithic and microkernel
    \item Some services in kernel space for performance
    \item Some services in user space for modularity
    \item Balance between speed and reliability
\end{itemize}

\textbf{Examples:}
\begin{itemize}
    \item \textbf{Windows NT kernel} --- Used in Windows, Xbox
    \item \textbf{macOS XNU (X is Not Unix)} --- Mach microkernel + BSD components
\end{itemize}

\begin{examplebox}[Tanenbaum-Torvalds Debate (1992)]
Famous debate between Andrew Tanenbaum (creator of MINIX, microkernel) and Linus Torvalds (creator of Linux, monolithic):

\textbf{Tanenbaum}: "Linux is obsolete" - argued monolithic kernels are outdated

\textbf{Torvalds}: Defended pragmatic monolithic design - performance and simplicity

\textbf{Outcome}: Both approaches have their merits. Linux dominates servers with monolithic-modular design, while QNX microkernel dominates automotive systems.
\end{examplebox}

\subsection{System Calls}

A \textbf{system call} is a mechanism provided by the kernel for programs in user space to request services from the kernel. System calls are the only way for applications to interact with hardware through the kernel.

\textbf{System Call Categories:}
\begin{enumerate}
    \item \textbf{Process Control}: \cmd{fork()}, \cmd{exec()}, \cmd{exit()}, \cmd{wait()}
    \item \textbf{File Management}: \cmd{open()}, \cmd{read()}, \cmd{write()}, \cmd{close()}
    \item \textbf{Device Management}: \cmd{ioctl()}, \cmd{read()}, \cmd{write()}
    \item \textbf{Information Maintenance}: \cmd{getpid()}, \cmd{time()}, \cmd{uname()}
    \item \textbf{Communication}: \cmd{pipe()}, \cmd{socket()}, \cmd{send()}, \cmd{receive()}
\end{enumerate}

\begin{examplebox}[System Call Flow]
When a program opens a file with \cmd{fopen()} in C:

\begin{enumerate}
    \item Application calls library function \cmd{fopen()}
    \item Library function calls system call \cmd{open()}
    \item CPU switches to kernel mode (Ring 0)
    \item Kernel validates parameters and permissions
    \item Kernel interacts with file system and disk driver
    \item Kernel returns file descriptor
    \item CPU switches back to user mode (Ring 3)
    \item Control returns to application
\end{enumerate}

This process is conceptually the same across all OSes, but implementation details differ.
\end{examplebox}

\section{Evolution of Operating Systems}
\label{sec:os-history}

\subsection{Brief Timeline}

Operating system development has gone through several important eras:

\begin{description}
    \item[1950s--1960s: Early Era] Batch processing systems, program cards, no interactive computing. Examples: IBM 701, UNIVAC.

    \item[1960s: Time-Sharing] CTSS (Compatible Time-Sharing System) at MIT - many users sharing computer time. Multics project (ambitious but failed, inspired Unix).

    \item[1969: Birth of Unix] Ken Thompson and Dennis Ritchie at Bell Labs created Unix. Simple, portable (written in C), with "do one thing well" philosophy.

    \item[1980s: PC Era] MS-DOS (1981) for IBM PC. Apple Macintosh (1984) with GUI. Windows 1.0 (1985) as a shell on top of DOS.

    \item[1991: Linux] Linus Torvalds, a student from Finland, released Linux kernel 0.01. Free, open source, Unix-compatible.

    \item[1993: Windows NT] Microsoft released Windows NT with hybrid kernel architecture for the enterprise market.

    \item[2001: Mac OS X] Apple released macOS X based on Darwin (BSD Unix + Mach microkernel). UNIX certified.

    \item[2000s: Modern Era] Windows XP unified consumer and NT lines. Linux dominated the server market. Open source momentum increased.

    \item[2007--2008: Mobile Revolution] iOS (2007) and Android (2008) redefined computing with a mobile-first approach.

    \item[2010s: Cloud Era] Linux dominated cloud computing (AWS, Google Cloud, Azure). Containers (Docker) revolutionized deployment.

    \item[2020s: Present] Hybrid computing, ARM processors (Apple Silicon), WSL brought Linux to Windows, security-focused development.
\end{description}

\section{Operating System Installation}
\label{sec:os-installation}

\subsection{Universal Installation Concepts}

Operating system installation involves the following general stages, applicable to all OSes:

\begin{enumerate}
    \item \textbf{Preparation} - Download ISO, create bootable media, backup data
    \item \textbf{Boot} - Configure BIOS/UEFI, boot from installation media
    \item \textbf{Partition} - Allocate disk space, create partitions
    \item \textbf{Installation} - Copy system files, install bootloader
    \item \textbf{Configuration} - Create user, configure network, initial settings
\end{enumerate}

\subsection{BIOS vs UEFI}

\subsection{Deployment Methods}

\subsubsection{Virtual Machine (Recommended for Learning)}

\textbf{Advantages:}
\begin{itemize}
    \item Safe experimentation - doesn't affect host system
    \item Snapshots for easy recovery
    \item Run multiple OSes in parallel
    \item No hardware risk
\end{itemize}

\textbf{Software:}
\begin{itemize}
    \item VirtualBox (free, cross-platform)
    \item VMware Workstation Player (free)
    \item QEMU/KVM (Linux native, free)
    \item Hyper-V (Windows built-in)
\end{itemize}

\subsubsection{Dual Boot}

Install multiple OSes on one machine. User selects OS at boot.

\textbf{Use case:} Native performance, hardware access, production use

\textbf{Risk:} Partition errors, bootloader conflicts, data loss if not careful

\subsubsection{Bare Metal}

Single OS installation, full hardware control.

\textbf{Use case:} Production servers, dedicated workstations

\section{Disk Partitioning and File Systems}
\label{sec:disk-partitioning}

\subsection{Partition Concepts}

A \textbf{partition} is a logical division of a physical disk. Each partition is treated as an independent storage unit by the OS.

\textbf{Why partition?}
\begin{itemize}
    \item \textbf{Organization} - Separate OS, user data, applications
    \item \textbf{Multi-OS} - Install multiple OSes on one disk
    \item \textbf{Backup/Recovery} - Easier to backup specific partitions
    \item \textbf{Security} - Isolate data with different permissions
    \item \textbf{Performance} - Optimize for different workload types
\end{itemize}

\subsection{Partition Tables}

\subsubsection{MBR (Master Boot Record)}

\textbf{Legacy scheme} - used with BIOS:
\begin{itemize}
    \item Maximum 4 primary partitions
    \item Extended partition can contain multiple logical partitions
    \item Maximum disk size: 2 TB
    \item Partition table size: 64 bytes
\end{itemize}

\subsubsection{GPT (GUID Partition Table)}

\textbf{Modern scheme} - used with UEFI:
\begin{itemize}
    \item Practically unlimited partitions (128 in Windows/Linux)
    \item Maximum disk size: 9.4 ZB (zettabytes)
    \item Redundant partition tables for reliability
    \item Required for UEFI Secure Boot
    \item Backward compatible with BIOS (Protective MBR)
\end{itemize}

\subsection{Linux Partition Scheme}

\subsubsection{Minimum Partitioning}

\begin{lstlisting}[caption={Minimal partition scheme}]
/           20 GB     ext4      Root filesystem
swap        2-4 GB    swap      Virtual memory
\end{lstlisting}

\subsubsection{Recommended Partitioning}

\begin{lstlisting}[caption={Recommended partition scheme}]
/boot/efi   512 MB    FAT32     EFI System Partition (UEFI)
/boot       1 GB      ext4      Kernel and bootloader
/           20 GB     ext4      Root filesystem
/home       50+ GB    ext4      User data
swap        4 GB      swap      Virtual memory
\end{lstlisting}

\textbf{Mount Point Explanation:}

\begin{description}
    \item[\texttt{/}] (root) System files, installed programs, configurations
    \item[\texttt{/boot}] Kernel, initramfs, GRUB bootloader
    \item[\texttt{/boot/efi}] EFI bootloader (UEFI systems only)
    \item[\texttt{/home}] User directories and personal data
    \item[\texttt{swap}] Virtual memory, hibernation support
\end{description}

\begin{tipbox}
\textbf{Why separate \texttt{/home}?}

Advantages:
\begin{itemize}
    \item Reinstall OS without losing user data
    \item Easier backup (backup only \texttt{/home})
    \item Upgrade distro while keeping settings
    \item Different filesystem or encryption for data
\end{itemize}
\end{tipbox}

\subsection{Swap Space}

\textbf{Swap} is disk space used as an extension of RAM (virtual memory).

\textbf{When is swap used?}
\begin{itemize}
    \item When RAM is full, inactive pages are moved to swap
    \item Hibernation (suspend-to-disk) - saves RAM contents to swap
\end{itemize}

\textbf{Swap Sizing Guidelines:}

\begin{table}[htbp]
    \centering
    \caption{Swap Size Recommendations}
    \label{tab:swap-sizing}
    \begin{tabular}{@{}ll@{}}
        \toprule
        \textbf{RAM Size} & \textbf{Swap Size} \\
        \midrule
        $\leq$ 2 GB & 2x RAM \\
        2--8 GB & Same as RAM \\
        $>$ 8 GB & 4--8 GB fixed \\
        Hibernation needed & RAM size + 2 GB \\
        \bottomrule
    \end{tabular}
\end{table}

\begin{warningbox}
Swap is not a substitute for insufficient RAM. Adding RAM is much more effective than creating large swap.
\end{warningbox}

\subsection{Filesystem Types}

\subsubsection{Cross-Platform Comparison}

\begin{table}[htbp]
    \centering
    \caption{Filesystem Comparison}
    \label{tab:filesystem-comparison}
    \begin{tabular}{@{}lllll@{}}
        \toprule
        \textbf{Filesystem} & \textbf{Platform} & \textbf{Max File} & \textbf{Journaling} & \textbf{Use Case} \\
        \midrule
        NTFS & Windows & 16 TB & Yes & Windows system \\
        APFS & macOS & 8 EB & CoW & Modern macOS \\
        ext4 & Linux & 16 TB & Yes & Linux default \\
        XFS & Linux & 8 EB & Yes & Large files \\
        Btrfs & Linux & 16 EB & CoW & Advanced features \\
        exFAT & Universal & 16 EB & No & USB drives \\
        \bottomrule
    \end{tabular}
\end{table}

\subsubsection{Linux Filesystems}

\textbf{ext4 (Fourth Extended Filesystem)}
\begin{itemize}
    \item Default for most Linux distributions
    \item Mature, stable, and well-tested
    \item Journaling for crash recovery
    \item Good performance for general use
\end{itemize}

\noindent
\textbf{XFS}
\begin{itemize}
    \item High-performance filesystem
    \item Excellent for large files and parallel I/O
    \item Default in Red Hat Enterprise Linux
    \item Cannot be shrunk (only expanded)
\end{itemize}

\noindent
\textbf{Btrfs (B-tree filesystem)}
\begin{itemize}
    \item Modern copy-on-write filesystem
    \item Built-in snapshots and compression
    \item RAID support
    \item Still maturing (production-ready in openSUSE)
\end{itemize}

\subsection{Practice: Manual Partitioning}

For advanced users, manual partitioning provides full control.

During Ubuntu installation, select "Custom storage layout":

\begin{lstlisting}[caption={Example manual partition layout}]
Device      Size    Type    Mount Point    Filesystem
/dev/sda1   512 MB  EFI     /boot/efi      FAT32
/dev/sda2   1 GB    ext4    /boot          ext4
/dev/sda3   20 GB   ext4    /              ext4
/dev/sda4   50 GB   ext4    /home          ext4
/dev/sda5   4 GB    swap    [swap]         swap
\end{lstlisting}

\subsubsection{Post-Installation Filesystem Commands}

\begin{lstlisting}[language=bash, caption={Filesystem verification and management}]
# Check disk usage
df -h

# Check disk partitions
lsblk
sudo fdisk -l

# Check filesystem type
lsblk -f
blkid

# Mount additional filesystem manually
sudo mkdir /mnt/data
sudo mount /dev/sdb1 /mnt/data

# Permanent mount - edit /etc/fstab
cat /etc/fstab
# Format: <device> <mount point> <type> <options> <dump> <pass>

# UUID-based mount (preferred)
UUID=xxx-xxx-xxx  /data  ext4  defaults  0  2
\end{lstlisting}

\begin{notebox}
\textbf{UUID vs Device Names}

Use UUID instead of \texttt{/dev/sdX} in fstab because:
\begin{itemize}
    \item Device names can change (sda → sdb when adding disks)
    \item UUID is a persistent identifier
    \item More reliable for production systems
\end{itemize}

Get UUID: \cmd{blkid} or \cmd{lsblk -f}
\end{notebox}

\section{Post-Installation Configuration}
\label{sec:post-installation}

After installation is complete, several important configurations should be performed.

\subsection{System Updates}

\textbf{Why important?}
\begin{itemize}
    \item Security patches for vulnerabilities
    \item Bug fixes and stability improvements
    \item New features and driver updates
\end{itemize}

\begin{lstlisting}[language=bash, caption={Update Ubuntu/Debian system}]
# Update package lists from repositories
sudo apt update

# Upgrade installed packages to latest versions
sudo apt upgrade

# Full system upgrade (handles dependencies)
sudo apt full-upgrade

# Remove unneeded packages
sudo apt autoremove

# Clean package cache
sudo apt clean
\end{lstlisting}

\subsection{Essential Software Installation}

\begin{lstlisting}[language=bash, caption={Install essential development tools}]
# Development tools
sudo apt install -y build-essential

# Version control
sudo apt install -y git

# Network utilities
sudo apt install -y curl wget net-tools

# Text editors
sudo apt install -y vim nano

# System monitoring
sudo apt install -y htop iotop

# Complete essentials in one command
sudo apt install -y \
    build-essential \
    git \
    curl \
    wget \
    vim \
    htop \
    tree \
    net-tools \
    openssh-server
\end{lstlisting}

\subsection{Network Connectivity Verification}

Ensure the system can connect to the internet.

\begin{lstlisting}[language=bash, caption={Check network status}]
# Check IP address
ip addr show

# Test internet connectivity
ping -c 4 google.com

# Check DNS
cat /etc/resolv.conf
\end{lstlisting}

\begin{tipbox}
If using VirtualBox, ensure the network adapter is set to "NAT" or "Bridged Adapter" for internet connection.
\end{tipbox}

\subsection{SSH Access (Optional)}

If you want remote access to the server via SSH (if already installed during installation):

\begin{lstlisting}[language=bash, caption={Check SSH status}]
# Check if SSH installed and running
sudo systemctl status ssh

# Get IP address for remote access
ip addr show
\end{lstlisting}

\begin{examplebox}[Remote Login via SSH]
From another computer on the same network:
\begin{lstlisting}[language=bash]
ssh username@192.168.1.100
\end{lstlisting}

Replace the IP address with your server's IP address.
\end{examplebox}

\subsection{Displaying System Information}

\subsubsection{Install Neofetch}

Neofetch is a popular tool for displaying system information with attractive visuals.

\begin{lstlisting}[language=bash, caption={Install neofetch}]

\end{lstlisting}

Neofetch will display:
\begin{itemize}

    \item OS information (distro, version, kernel)
    \item CPU and memory usage
    \item Disk space
    \item System uptime
    \item And other information in an easy-to-read format
\end{itemize}

\end{tipbox}

\section{Summary}
\label{sec:summary}

In this chapter, we have learned fundamental operating system concepts and installation practices:

\subsection{Operating System Concepts}

\begin{itemize}
    \item \textbf{Definition}: OS is a resource manager and extended machine
    \item \textbf{Main Functions}: Process, Memory, File, I/O Management, and Security
    \item \textbf{OS Types}: Desktop, Server, Mobile, Real-Time, Embedded
    \item \textbf{Kernel Architectures}:
    \begin{itemize}
        \item Monolithic (Linux) - Performance
        \item Microkernel (QNX) - Reliability
        \item Hybrid (Windows, macOS) - Balance
    \end{itemize}
    \item \textbf{System Calls}: Interface between user space and kernel services
\end{itemize}

\subsection{Operating System Comparison}

\begin{itemize}
    \item \textbf{Windows}: Desktop dominance, gaming, business software
    \item \textbf{macOS}: Creative professionals, hardware integration
    \item \textbf{Linux}: Server dominance, open source, flexibility
    \item \textbf{Android/iOS}: Mobile platforms
\end{itemize}

\subsection{Practical Skills}

\begin{itemize}
    \item Installation process (VM setup, Ubuntu Server)
    \item Partitioning concepts (MBR vs GPT, partition schemes)

    \item Post-installation: system updates and basic configuration
    \item System information gathering with neofetch and basic commands
\end{itemize}

\subsection{Key Takeaways}

\begin{enumerate}
    \item OS concepts are universal - applicable across various platforms
    \item Linux is excellent for learning: open, free, industry-relevant
    \item Virtual machines provide a safe learning environment
    \item Proper partitioning is important for flexibility and recovery
    \item System updates should be performed regularly
    \item Basic system monitoring tools help understand system status
\end{enumerate}
