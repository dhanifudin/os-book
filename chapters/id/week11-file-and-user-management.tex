\chapter{Manajemen File \& User/Group}
\label{ch:file-and-user-management}

\begingroup
\small
\setstretch{0.85}
\setlength{\parskip}{0pt}
\setlist{nosep}

Bab ini merangkum fondasi administrasi akses di Linux: permission Unix klasik,
ACL untuk kasus yang lebih granular, manajemen user dan group, penggunaan
\cmd{sudo} dan \cmd{su}, serta pembatasan ruang disk dengan quota. Fokus bab ini
adalah memahami \emph{model kontrol akses} Linux secara utuh: siapa memiliki file,
siapa boleh mengakses, bagaimana hak administratif didelegasikan, dan bagaimana
penggunaan sumber daya dibatasi di sistem multi-pengguna.

\textbf{Tujuan Praktikum}

Setelah menyelesaikan bab ini, pembaca diharapkan mampu:

\begin{enumerate}
    \item membaca dan mengubah permission file/direktori;
    \item membedakan peran owner, group, dan others;
    \item menggunakan ACL saat permission standar tidak cukup;
    \item membuat, memodifikasi, dan menghapus user serta group;
    \item mengelola hak administratif dengan \cmd{sudo} secara aman; dan
    \item mengaktifkan serta memeriksa disk quota untuk user atau group.
\end{enumerate}

\section{Sistem Kontrol Akses (Permissions)}
\label{sec:permissions}
%% ========================================================================

\textbf{Penjelasan Konsep}

Linux mewarisi model kontrol akses Unix yang sederhana namun kuat. Setiap file dan
direktori selalu memiliki tiga identitas akses:

\begin{description}
    \item[Owner] pengguna yang memiliki file.
    \item[Group] group yang terkait dengan file.
    \item[Others] semua pengguna lain di luar dua entitas di atas.
\end{description}

Untuk masing-masing entitas itu tersedia tiga izin dasar: baca, tulis, dan eksekusi.

\begin{table}[htbp]
    \centering
    \caption{Makna izin dasar Linux}
    \label{tab:permissions-type}
    \begin{tblr}{
        colspec = {lX[l]X[l]},
        width = \linewidth,
        hlines,
        vlines,
        row{1} = {font=\bfseries},
        cells = {font=\small}
    }
    \textbf{Simbol} & \textbf{Pada file} & \textbf{Pada direktori} \\
    \texttt{r} & Membaca isi file & Melihat isi direktori \\
    \texttt{w} & Mengubah isi file & Membuat atau menghapus entri di direktori \\
    \texttt{x} & Menjalankan file & Masuk ke direktori \\
    \end{tblr}
\end{table}

\begin{notebox}
Hak \texttt{w} pada file hanya mengubah isi file. Menghapus file ditentukan oleh
izin pada direktori yang menampung file tersebut.
\end{notebox}

\textbf{Perintah yang Digunakan}

\begin{itemize}
    \item \texttt{ls -l}: melihat tipe file, permission, owner, dan group.
    \item \texttt{chmod}: mengubah permission file atau direktori.
    \item \texttt{chown}: mengubah owner dan/atau group pemilik file.
    \item \texttt{chgrp}: mengubah group pemilik file.
    \item \texttt{umask}: melihat atau mengubah permission default file baru.
\end{itemize}

\subsection{Membaca Output \texttt{ls -l}}

Output \cmd{ls -l} merangkum tipe file, permission, owner, group, ukuran, dan waktu.

\begin{lstlisting}[language=bash, caption={Membaca permission dengan ls -l}]
$ ls -l /etc/passwd
-rw-r--r-- 1 root root 2847 Jan 15 10:30 /etc/passwd
\end{lstlisting}

Interpretasi string permission:

\begin{itemize}
    \item karakter pertama: tipe file (\texttt{-}, \texttt{d}, \texttt{l}, dll.)
    \item tiga karakter berikutnya: permission owner
    \item tiga berikutnya: permission group
    \item tiga terakhir: permission others
\end{itemize}

Contoh \texttt{-rwxr-x---} berarti file biasa, owner punya hak penuh, group dapat
baca dan eksekusi, others tidak punya akses.

\subsection{Notasi Simbolik dan Oktal}

Permission dapat ditulis dalam dua bentuk:

\begin{itemize}
    \item \textbf{simbolik}: relatif, misalnya \texttt{u+x}, \texttt{go-w}
    \item \textbf{oktal}: absolut, misalnya \texttt{755}, \texttt{640}, \texttt{600}
\end{itemize}

\begin{table}[htbp]
    \centering
    \caption{Konversi permission ke notasi oktal}
    \label{tab:octal-permissions}
    \begin{tblr}{
        colspec = {lccX[l]},
        width = \linewidth,
        hlines,
        vlines,
        row{1} = {font=\bfseries},
        cells = {font=\small}
    }
    \textbf{Izin} & \textbf{Biner} & \textbf{Oktal} & \textbf{Makna} \\
    \texttt{---} & 000 & 0 & Tidak ada izin \\
    \texttt{r--} & 100 & 4 & Read saja \\
    \texttt{rw-} & 110 & 6 & Read dan write \\
    \texttt{rwx} & 111 & 7 & Read, write, execute \\
    \end{tblr}
\end{table}

Pola yang paling umum:

\begin{itemize}
    \item \texttt{755}: direktori atau program publik
    \item \texttt{644}: file biasa
    \item \texttt{600}: file privat seperti kunci SSH
    \item \texttt{700}: skrip atau direktori privat
\end{itemize}

\subsection{\cmd{chmod}, \cmd{chown}, dan \cmd{chgrp}}

Tiga perintah inti pengelolaan permission adalah:

\begin{itemize}
    \item \cmd{chmod}: mengubah permission
    \item \cmd{chown}: mengubah owner dan/atau group
    \item \cmd{chgrp}: mengubah group saja
\end{itemize}

\begin{lstlisting}[language=bash, caption={Perintah dasar permission dan ownership}]
# chmod simbolik
chmod +x script.sh
chmod u=rw,g=r,o= file.txt
chmod go-w file.txt

# chmod oktal
chmod 644 /etc/app.conf
chmod 755 /usr/local/bin/my-script.sh
chmod 600 ~/.ssh/id_rsa

# ownership
sudo chown alice report.txt
sudo chown alice:developers report.txt
sudo chgrp developers report.txt
\end{lstlisting}

Prinsip pemakaian:

\begin{itemize}
    \item gunakan notasi simbolik untuk perubahan kecil dan bertahap;
    \item gunakan notasi oktal saat ingin hasil akhir pasti, terutama di skrip;
    \item selalu verifikasi perubahan rekursif dengan \cmd{ls -la} pada beberapa file.
\end{itemize}

\begin{warningbox}
Hindari \texttt{chmod 777} kecuali benar-benar memahami risikonya. Permission ini
memberikan hak tulis dan eksekusi ke semua pengguna.
\end{warningbox}

\subsection{Special Permission Bits}

Selain sembilan bit \texttt{rwx}, Linux memiliki tiga bit khusus:

\begin{description   \item[SUID] program berjalan dengan UID pemilik file. Contoh klasik:
        \cmd{/usr/bin/passwd} perlu menulis ke \file{/etc/shadow}.
    \item[SGID] pada file executable proses berjalan dengan GID file; pada direktori,
        file baru mewarisi group direktori.
    \item[Sticky bit] pada direktori, pengguna hanya boleh menghapus file miliknya
        sendiri walau direktori dapat ditulis banyak orang.
\end{description}

\begin{lstlisting}[language=bash, caption={Contoh special bits}]
# SUID
ls -l /usr/bin/passwd
sudo chmod 4755 /usr/local/bin/my-tool

# SGID pada direktori bersama
sudo mkdir /srv/project
sudo chown root:developers /srv/project
sudo chmod 2775 /srv/project

# Sticky bit
ls -ld /tmp
sudo chmod 1777 /shared/uploads
\end{lstlisting}

\begin{tipbox}
Kombinasi SGID + sticky bit sering dipakai untuk direktori kolaborasi: SGID menjaga
group tetap konsisten, sticky bit mencegah saling hapus file.
\end{tipbox}

\subsection{umask --- Nilai Default Izin Baru}

\textbf{umask} adalah masker yang \emph{mengurangi} permission default file baru.
Secara praktis, file reguler berangkat dari \texttt{666}, direktori dari \texttt{777},
lalu dikurangi oleh nilai umask.

umask

\begin{notebox}
umask tidak pernah menambahkan execute pada file reguler. Jika file harus executable,
gunakan \cmd{chmod} secara eksplisit.
\end{notebox}

\subsection*{Praktikum 9.1 --- Permissions}

\textbf{Tujuan}: membaca permission, mengubahnya dengan aman, dan memahami efek
\cmd{chmod}, \cmd{chown}, serta \cmd{umask} pada file nyata.

\textbf{Langkah 1}: Buat direktori kerja dan dua file uji.

\begin{lstlisting}[language=bash, caption={Menyiapkan file uji permission}]
mkdir ~/lab-permissions && cd ~/lab-permissions
echo "data rahasia" > secret.txt
echo '#!/bin/bash' > myscript.sh
echo 'echo Hello' >> myscript.sh
ls -la
\end{lstlisting}

Perhatikan permission awal kedua file. Biasanya file baru tidak memiliki bit execute.

\textbf{Langkah 2}: Jadikan \file{secret.txt} privat hanya untuk owner.

\begin{lstlisting}[language=bash, caption={Membuat file privat}]
chmod 600 secret.txt
ls -l secret.txt
\end{lstlisting}

Permission \texttt{600} berarti owner dapat membaca dan menulis, sedangkan group dan
others tidak memiliki akses.

\textbf{Langkah 3}: Jadikan \file{myscript.sh} dapat dijalankan.

\begin{lstlisting}[language=bash, caption={Menjadikan skrip executable}]
chmod 755 myscript.sh
ls -l myscript.sh
./myscript.sh
\end{lstlisting}

Permission \texttt{755} memberi hak penuh ke owner, dan hak baca+execute ke group serta
others. Tanpa bit execute, file skrip tidak bisa dijalankan langsung.

\textbf{Langkah 4}: Buat direktori bersama dan amati efek SGID sederhana.

\begin{lstlisting}[language=bash, caption={Direktori bersama dengan SGID}]
mkdir shared-dir
chmod g+s shared-dir
ls -ld shared-dir
\end{lstlisting}

Jika output menampilkan huruf \texttt{s} pada posisi group execute, berarti SGID aktif.

\textbf{Langkah 5}: Uji efek \cmd{umask} pada file baru.

\begin{lstlisting}[language=bash, caption={Mengamati efek umask}]
umask
umask 027
touch testfile-027
ls -l testfile-027
\end{lstlisting}

\textbf{Analisis}

\begin{enumerate}
    \item Mengapa \file{secret.txt} tidak dapat dibaca oleh group dan others setelah
        \cmd{chmod 600}?
    \item Apa perbedaan arti \texttt{600} dan \texttt{755} terhadap file yang diuji?
    \item Setelah \cmd{umask 027}, permission apa yang dihasilkan untuk file baru, dan
        mengapa bukan \texttt{777}?
\end{enumerate}

\textbf{Tantangan}

Ubah owner atau group salah satu file uji ke akun atau group lain yang tersedia di sistem,
kemudian jelaskan perubahan output \cmd{ls -l} sebelum dan sesudahnya.

\section{Access Control Lists (ACLs)}
\label{sec:acls}
%% ========================================================================

Permission Unix klasik sangat cocok untuk mayoritas kasus, tetapi ia hanya mengenal
satu owner dan satu group. Masalah muncul saat akses perlu diberikan ke satu pengguna
tertentu tanpa mengubah owner file dan tanpa memasukkan pengguna itu ke group utama.

Contoh masalah yang umum:

\begin{examplebox}[Mengapa ACL diperlukan]
File \file{laporan.txt} dimiliki \texttt{alice} dan group \texttt{finance}. User
\texttt{bob} perlu membaca file itu, tetapi Anda tidak ingin semua anggota group lain
ikut mendapat akses. ACL memungkinkan Anda memberi izin hanya ke \texttt{bob}.
\end{examplebox}

ACL menambahkan aturan akses \emph{tambahan} di atas permission standar. Ada dua jenis:

\begin{description}
    \item[Access ACL] berlaku langsung pada file atau direktori saat ini.
    \item[Default ACL] hanya untuk direktori, dan diwariskan ke konten baru di dalamnya.
\end{description}

\begin{notebox}
Di Ubuntu 22.04, filesystem modern seperti ext4, XFS, dan Btrfs umumnya sudah mendukung
ACL. Jika utilitasnya belum tersedia, instal paket \texttt{acl}.
\end{notebox}

\textbf{Perintah yang Digunakan}

\begin{itemize}
    \item \texttt{getfacl file}: menampilkan ACL lengkap file atau direktori.
    \item \texttt{setfacl -m ...}: menambah atau mengubah entri ACL.
    \item \texttt{setfacl -x ...}: menghapus satu entri ACL.
    \item \texttt{setfacl -b file}: menghapus semua ACL tambahan.
    \item \texttt{setfacl -d -m ... dir}: menetapkan \textit{default ACL} pada direktori.
\end{itemize}

\subsection{Langkah 1: Membaca ACL yang Ada}

Perintah pertama yang perlu dikenal adalah \cmd{getfacl}. Fungsinya mirip
\cmd{ls -l}, tetapi lebih detail.

\begin{lstlisting}[language=bash, caption={Membaca ACL dasar dengan getfacl}]
sudo apt install -y acl
getfacl file.txt

# contoh output minimum
# user::rw-
# group::r--
# other::r--
\end{lstlisting}

Jika file belum memiliki ACL tambahan, output \cmd{getfacl} hanya menampilkan tiga
entri dasar yang sepadan dengan permission Unix biasa: owner, group, dan others.
Begitu ACL tambahan diterapkan, Anda akan melihat entri user/group spesifik dan
sering juga sebuah \texttt{mask}.

Format entri yang paling penting adalah:

\begin{table}[htbp]
    \centering
    \caption{Format entri ACL yang umum}
    \label{tab:setfacl-entries}
    \begin{tblr}{
        colspec = {lX[l]X[l]},
        width = \linewidth,
        hlines,
        vlines,
        row{1} = {font=\bfseries},
        cells = {font=\small}
    }
    \textbf{Entri} & \textbf{Contoh} & \textbf{Arti} \\
    \texttt{u::izin} & \texttt{u::rw-} & Permission owner \\
    \texttt{u:nama:izin} & \texttt{u:bob:r--} & ACL untuk user tertentu \\
    \texttt{g::izin} & \texttt{g::r--} & Permission group standar \\
    \texttt{g:nama:izin} & \texttt{g:audit:rw-} & ACL untuk group tertentu \\
    \texttt{o::izin} & \texttt{o::---} & Permission others \\
    \texttt{m::izin} & \texttt{m::rw-} & Mask ACL \\
    \end{tblr}
\end{table}

Ketika ACL aktif, \cmd{ls -l} menampilkan tanda \texttt{+} di akhir string permission,
misalnya \texttt{-rw-r-----+}.

\subsection{Langkah 2: Menambahkan ACL untuk Satu User atau Group}

Perintah utama untuk membuat atau mengubah ACL adalah \cmd{setfacl}. Mulailah dari
kasus paling sederhana: memberi akses baca ke satu user.

\begin{lstlisting}[language=bash, caption={Menambahkan ACL secara bertahap}]
# beri bob hak baca
setfacl -m u:bob:r file.txt

# beri group audit hak baca-tulis
setfacl -m g:audit:rw file.txt

# lihat hasilnya
getfacl file.txt
\end{lstlisting}

Cara membacanya:

\begin{itemize}
    \item \texttt{-m} berarti \emph{modify}: tambah atau ubah entri;
    \item \texttt{u:bob:r} berarti user \texttt{bob} mendapat izin baca;
    \item \texttt{g:audit:rw} berarti group \texttt{audit} mendapat izin baca dan tulis.
\end{itemize}

Jika ACL tidak lagi diperlukan, hapus salah satu entri atau semua entri tambahan:

\begin{lstlisting}[language=bash, caption={Menghapus ACL}]
setfacl -x u:bob file.txt
setfacl -x g:audit file.txt
setfacl -b file.txt
\end{lstlisting}

\texttt{-x} menghapus satu entri tertentu. Opsi \texttt{-b} menghapus seluruh ACL
tambahan dan mengembalikan file ke model permission Unix standar.

\subsection{Langkah 3: Memahami Mask dan Izin Efektif}

Begitu ACL tambahan dipasang, Linux biasanya membuat \textbf{mask}. Untuk pemula,
bayangkan mask sebagai \emph{batas atas} izin yang boleh benar-benar berlaku untuk
entri ACL tertentu.

\begin{lstlisting}[language=bash, caption={Mask ACL dan izin efektif}]
getfacl ~/report.txt
# user::rw-
# user:charlie:rwx        #effective:rw-
# group::r--              #effective:r--
# group:audit:rw-         #effective:rw-
# mask::rw-
# other::---

setfacl -m m::r-- ~/report.txt
chmod g-w ~/report.txt
\end{lstlisting}

Pada contoh di atas, \texttt{user:charlie:rwx} tidak benar-benar mendapat \texttt{rwx}
karena mask hanya mengizinkan \texttt{rw-}. Itulah sebabnya \cmd{getfacl} menampilkan
komentar \texttt{\#effective:rw-}.

Aturan praktis yang perlu diingat:

\begin{itemize}
    \item owner dan others tidak difilter oleh mask;
    \item named user, group standar, dan named group bisa dipersempit oleh mask;
    \item \cmd{chmod} pada file ber-ACL sering memengaruhi mask;
    \item jika hasilnya membingungkan, selalu cek lagi dengan \cmd{getfacl}.
\end{itemize}

\subsection{Langkah 4: Default ACL untuk Direktori}

Setelah paham ACL pada satu file, langkah berikutnya adalah ACL yang diwariskan otomatis.
Inilah fungsi \textbf{default ACL}. Ia sangat berguna untuk direktori proyek bersama.

\begin{lstlisting}[language=bash, caption={Default ACL pada direktori kolaborasi}]
mkdir ~/project
setfacl -d -m g:developers:rwx ~/project
setfacl -d -m u:deploy:r-x,g:auditors:r-- ~/project

touch ~/project/newfile.txt
getfacl ~/project/newfile.txt

mkdir ~/project/subdir
getfacl ~/project/subdir

setfacl -x d:g:developers ~/project
setfacl -k ~/project
\end{lstlisting}

Alur kerjanya bertahap:

\begin{enumerate}
    \item tambahkan default ACL ke direktori dengan opsi \texttt{-d -m};
    \item buat file atau subdirektori baru;
    \item periksa ACL hasil warisan dengan \cmd{getfacl};
    \item hapus default ACL bila tidak lagi dibutuhkan.
\end{enumerate}

\begin{notebox}
File baru tidak mewarisi execute dari default ACL bila ia file reguler; subdirektori
tetap mempertahankan execute karena \texttt{x} pada direktori berarti izin masuk.
\end{notebox}

\subsection*{Praktikum 9.2 --- ACL}

\textbf{Tujuan}: memahami ACL dari nol: melihat kondisi awal, menambah akses untuk satu
user, lalu membuat direktori yang mewariskan ACL otomatis.

\textbf{Langkah 1}: Siapkan file dan lihat permission standar tanpa ACL tambahan.

\begin{lstlisting}[language=bash, caption={Menyiapkan file uji ACL}]
mkdir ~/lab-acl && cd ~/lab-acl
echo "Data penting" > confidential.txt
chmod 640 confidential.txt
ls -l confidential.txt
getfacl confidential.txt
\end{lstlisting}

Pada tahap ini, \cmd{getfacl} hanya menampilkan tiga entri dasar: owner, group, dan
others. Belum ada named user atau named group.

\textbf{Langkah 2}: Beri akses baca ke satu user tertentu tanpa mengubah owner atau group.

\begin{lstlisting}[language=bash, caption={Menambahkan ACL untuk satu user}]
setfacl -m u:userA:r confidential.txt
ls -l confidential.txt
getfacl confidential.txt
\end{lstlisting}

Perhatikan dua perubahan:
\begin{itemize}
    \item output \cmd{ls -l} menampilkan tanda \texttt{+};
    \item output \cmd{getfacl} kini memiliki entri \texttt{user:userA:r--}.
\end{itemize}

\textbf{Langkah 3}: Buat direktori bersama yang mewariskan ACL ke file baru.

\begin{lstlisting}[language=bash, caption={Default ACL pada direktori}]
mkdir shared
setfacl -d -m u:userA:rwx shared
setfacl -d -m u:userB:r-x shared
getfacl shared

touch shared/inherited.txt
getfacl shared/inherited.txt
\end{lstlisting}

\textbf{Analisis}

\begin{enumerate}
    \item Mengapa \cmd{getfacl confidential.txt} awalnya tidak menampilkan user tertentu?
    \item Setelah \cmd{setfacl -m u:userA:r confidential.txt}, apa perbedaan output
        \cmd{ls -l} dan \cmd{getfacl}?
    \item Mengapa file \texttt{inherited.txt} mewarisi ACL dari direktori \texttt{shared}?
\end{enumerate}

\textbf{Tantangan}

Tambahkan satu ACL lagi agar group \texttt{readonly-group} hanya dapat membaca
\file{confidential.txt}. Setelah itu, hapus ACL untuk \texttt{userA} dan verifikasi
hasil akhirnya dengan \cmd{getfacl}.

\section{Manajemen User dan Group}
\label{sec:user-group-management}
%% ========================================================================

\textbf{Penjelasan Konsep}

Linux menyimpan identitas pengguna di tiga file: \file{/etc/passwd} (data dasar user,
dapat dibaca semua orang), \file{/etc/shadow} (hash password dan aging policy, hanya
root), dan \file{/etc/group} (definisi group). Sistem ini memisahkan informasi publik
dari rahasia keamanan.

\textbf{Perintah Utama}

\begin{itemize}
    \item \texttt{useradd}, \texttt{usermod}, \texttt{userdel}: kelola akun user.
    \item \texttt{groupadd}, \texttt{groupmod}, \texttt{groupdel}: kelola group.
    \item \texttt{passwd}: ubah atau kunci password.
    \item \texttt{chage}: atur kebijakan umur password.
    \item \texttt{id}, \texttt{groups}: lihat informasi user dan group.
\end{itemize}

\subsection{Membaca Informasi User dan Group}

\begin{lstlisting}[language=bash, caption={Perintah query user dan group}]
id alice
groups alice
getent passwd alice
getent group developers
grep "^alice:" /etc/passwd
sudo grep "^alice:" /etc/shadow
\end{lstlisting}

\begin{notebox}
\cmd{id} lebih akurat daripada \cmd{grep /etc/group} karena menampilkan semua group
user, termasuk primary group.
\end{notebox}

\subsection{Siklus Hidup User: Buat, Modifikasi, Hapus}

\begin{lstlisting}[language=bash, caption={Pengelolaan akun user}]
# buat user dengan home directory dan shell
sudo useradd -m -s /bin/bash alice
sudo passwd alice

# modifikasi: tambah group, ubah shell, lock/unlock
sudo usermod -aG developers,sudo alice
sudo usermod -s /bin/zsh alice
sudo usermod -L alice
sudo usermod -U alice

# hapus user (dengan atau tanpa home directory)
sudo userdel alice
sudo userdel -r alice
\end{lstlisting}

\textbf{Opsi penting}:
\begin{itemize}
    \item \texttt{-m}: buat home directory otomatis
    \item \texttt{-s}: tentukan shell login
    \item \texttt{-aG}: tambah group tanpa menghapus group lama
    \item \texttt{-L}/\texttt{-U}: lock/unlock akun
    \item \texttt{-r}: hapus home directory saat menghapus user
\end{itemize}

\begin{warningbox}
Gunakan \cmd{usermod -aG}, bukan \cmd{usermod -G}. Tanpa \texttt{-a}, semua
supplementary group lama akan diganti.
\end{warningbox}

\subsection*{Praktikum 9.3A --- Membuat dan Mengelola User}

\textbf{Tujuan}: membuat user baru, memodifikasi propertinya, dan memahami perbedaan
opsi \cmd{useradd} dan \cmd{usermod}.

\begin{lstlisting}[language=bash, caption={Latihan user management}]
# buat dua user
sudo useradd -m -s /bin/bash userA
sudo useradd -m -s /bin/bash userB
sudo passwd userA
sudo passwd userB

# verifikasi
id userA
getent passwd userA

# modifikasi shell userA
sudo usermod -s /bin/zsh userA
getent passwd userA

# lock dan unlock userB
sudo usermod -L userB
sudo passwd -S userB
sudo usermod -U userB
sudo passwd -S userB
\end{lstlisting}

\textbf{Pertanyaan}:
\begin{enumerate}
    \item Apa perbedaan output \cmd{id userA} sebelum dan sesudah menambah group?
    \item Bagaimana status \cmd{passwd -S userB} berubah saat akun di-lock?
\end{enumerate}

\subsection{Pengelolaan Group}

\begin{lstlisting}[language=bash, caption={Operasi group}]
sudo groupadd developers
sudo groupadd -g 2000 finance
sudo groupmod -n devteam developers
sudo gpasswd -a alice devteam
sudo gpasswd -d alice devteam
sudo groupdel devteam
\end{lstlisting}

\begin{notebox}
Perubahan group baru terasa penuh setelah user logout-login atau membuka subshell
dengan \cmd{newgrp nama-group}.
\end{notebox}

\subsection*{Praktikum 9.3B --- Group Management}

\textbf{Tujuan}: membuat group, menambahkan user ke group, dan memverifikasi keanggotaan.

\begin{lstlisting}[language=bash, caption={Latihan group management}]
# buat dua group
sudo groupadd labgroup
sudo groupadd readonly-group

# tambahkan userA ke kedua group
sudo usermod -aG labgroup,readonly-group userA

# tambahkan userB hanya ke readonly-group
sudo usermod -aG readonly-group userB

# verifikasi
id userA
id userB
getent group labgroup
getent group readonly-group
\end{lstlisting}

\textbf{Pertanyaan}:
\begin{enumerate}
    \item Apa yang ditampilkan \cmd{id userA} vs \cmd{groups userA}?
    \item Mengapa \texttt{-a} pada \cmd{usermod -aG} penting?
\end{enumerate}

\subsection{Kebijakan Password dan Aging}

\begin{lstlisting}[language=bash, caption={Password policy dengan chage}]
# lihat status aging
sudo chage -l alice

# set kebijakan: password valid 90 hari, warning 14 hari sebelumnya
sudo chage -M 90 -m 7 -W 14 alice

# kunci akun 30 hari setelah password expired
sudo chage -I 30 alice

# set tanggal kedaluwarsa akun
sudo chage -E 2025-12-31 alice

# paksa ganti password segera
sudo chage -d 0 alice
sudo passwd -e alice
\end{lstlisting}

\begin{table}[htbp]
    \centering
    \caption{Opsi \cmd{chage} yang paling penting}
    \label{tab:chage-options}
    \begin{tblr}{
        colspec = {lcX[l]},
        width = \linewidth,
        hlines,
        vlines,
        row{1} = {font=\bfseries},
        cells = {font=\small}
    }
    \textbf{Opsi} & \textbf{Nama} & \textbf{Arti} \\
    \texttt{-l} & list & Tampilkan status aging \\
    \texttt{-M N} & maxdays & Password wajib diganti tiap N hari \\
    \texttt{-m N} & mindays & Minimal N hari sebelum boleh ganti \\
    \texttt{-W N} & warndays & Peringatan N hari sebelum expired \\
    \texttt{-I N} & inactive & Kunci akun N hari setelah expired \\

\subsection*{Praktikum 9.3C --- Password Aging Policy}

\textbf{Tujuan}: menerapkan kebijakan umur password dan mengamati efeknya.

\begin{lstlisting}[language=bash, caption={Latihan password policy}]
# set aging policy untuk userA
sudo chage -M 60 -W 7 -m 1 userA
sudo chage -l userA

# paksa userA ganti password saat login pertama
sudo chage -d 0 userA

# kunci password userB
sudo passwd -l userB
sudo passwd -S userB

# unlock kembali
sudo passwd -u userB
sudo passwd -S userB
\end{lstlisting}

\textbf{Pertanyaan}:
\begin{enumerate}
    \item Apa arti nilai yang ditampilkan \cmd{chage -l userA}?
    \item Bagaimana cara membuktikan userB terkunci dari output \cmd{passwd -S}?
    \item Kapan sebaiknya menggunakan \cmd{chage -d 0} vs \cmd{passwd -e}?
\end{enumerate}

\textbf{Tantangan}

Buat user bernama \texttt{intern} yang:
\begin{itemize}
    \item memiliki shell \texttt{/bin/bash};
    \item menjadi anggota \texttt{labgroup};
    \item dipaksa ganti password pada login pertama;
    \item password expired setelah 45 hari dengan warning 7 hari sebelumnya.
\end{itemize}

\section{Konfigurasi sudo dan su}
\label{sec:sudo-su}
%% ========================================================================

\textbf{Penjelasan Konsep}

\subsection{Perbedaan \cmd{su} dan \cmd{sudo}}

\cmd{su} berpindah identitas pengguna, sedangkan \cmd{sudo} menjalankan perintah
tertentu dengan privilege lebih tinggi berdasarkan aturan kebijakan.

\begin{table}[htbp]
    \centering
    \caption{Perbandingan \cmd{su} dan \cmd{sudo}}
    \label{tab:su-vs-sudo}
    \begin{tblr}{
        colspec = {lX[l]X[l]},
        width = \linewidth,
        hlines,
        vlines,
        row{1} = {font=\bfseries},
        cells = {font=\small}
    }
    \textbf{Aspek} & \textbf{su} & \textbf{sudo} \\
    Autentikasi & Password user target & Password pengguna sendiri \\
    Scope & Beralih penuh ke sesi lain & Menjalankan perintah tertentu \\
    Logging & Minimal / tidak default & Tercatat di log sistem \\
    Granularitas & Kasar & Sangat granular \\
    Praktik modern & Lebih terbatas & Direkomendasikan \\
    \end{tblr}
\end{table}

\begin{notebox}
Di Ubuntu, akun root biasanya dinonaktifkan untuk login langsung; karena itu
\cmd{sudo} menjadi mekanisme standar administrasi.
\end{notebox}

\textbf{Perintah yang Digunakan}

\begin{itemize}
    \item \texttt{su - user}: berpindah ke user lain dengan login environment penuh.
    \item \texttt{sudo perintah}: jalankan satu perintah dengan privilege lebih tinggi.
    \item \texttt{sudo -i}: buka shell root dengan login environment.
    \item \texttt{sudo -l}: lihat hak sudo yang tersedia.
    \item \texttt{visudo}: edit aturan sudoers dengan validasi sintaks.
\end{itemize}

\subsection{Pemakaian Dasar \cmd{su} dan \cmd{sudo}}

\begin{lstlisting}[language=bash, caption={Perintah su dan sudo yang paling sering dipakai}]
# su
su - alice
su - alice -c "ls -la /home/alice"

# sudo
sudo apt update
sudo -u alice cat /home/alice/report.txt
sudo -i
sudo -s
sudo -l
sudo -k
sudo -e /etc/hosts
\end{lstlisting}

Pedoman ringkas:

\begin{itemize}
    \item gunakan \cmd{su - user}, bukan \cmd{su user}, jika memang harus berpindah sesi;
    \item gunakan \cmd{sudo -i} untuk shell root dengan login environment penuh;
    \item gunakan \cmd{sudo -e} atau \cmd{sudoedit} untuk mengedit file sistem lebih aman.
\end{itemize}

\subsection{Konfigurasi sudoers yang Aman}

Konfigurasi utama sudo berada di \file{/etc/sudoers}, tetapi praktik terbaik adalah
menyimpan aturan tambahan di \dir{/etc/sudoers.d/}.

\begin{warningbox}
Selalu edit aturan sudo dengan \cmd{visudo}. Kesalahan sintaks dapat mengunci akses
administratif Anda ke sistem.
\end{warningbox}

Format aturan dasar:

\begin{center}
\texttt{WHO\ \\ WHERE=(AS\_WHO)\ \\ COMMAND}
\end{center}

\begin{lstlisting}[language=bash, caption={Contoh aturan sudoers yang representatif}]
# akses penuh untuk user tertentu
alice ALL=(ALL:ALL) ALL

# akses apt tanpa password
bob ALL=(root) NOPASSWD: /usr/bin/apt

# group sudo bawaan Ubuntu
%sudo ALL=(ALL:ALL) ALL

# izin terbatas untuk service nginx
%webadmin ALL=(root) /bin/systemctl start nginx, \
                     /bin/systemctl stop nginx, \
                     /bin/systemctl restart nginx, \
                     /bin/systemctl status nginx
\end{lstlisting}

\begin{lstlisting}[language=bash, caption={Mengelola file sudoers}]
sudo visudo
sudo visudo -f /etc/sudoers.d/developers
sudo visudo -c
sudo grep sudo /var/log/auth.log | tail -20
\end{lstlisting}

\subsection*{Praktikum 9.4 --- Konfigurasi sudo}

\textbf{Tujuan}: membuat aturan sudo terbatas, memverifikasi hak akses, dan membaca log.

\textbf{Langkah 1}: Buat file konfigurasi sudo khusus untuk \texttt{userA}.

\begin{lstlisting}[language=bash, caption={Membuat file sudoers terpisah}]
sudo visudo -f /etc/sudoers.d/lab-userA
\end{lstlisting}

Perintah ini membuka editor aman khusus untuk file sudoers baru. Jika sintaks salah,
\cmd{visudo} akan memperingatkan sebelum file disimpan.

Isi file dengan aturan berikut:

\begin{lstlisting}[language=bash, caption={Isi konfigurasi sudo untuk userA}]
userA ALL=(root) NOPASSWD: /usr/bin/apt update, /usr/bin/apt upgrade
userA ALL=(root) /bin/systemctl status *
\end{lstlisting}

Baris pertama berarti \texttt{userA} boleh menjalankan dua perintah \cmd{apt} tanpa
password. Baris kedua berarti \texttt{userA} boleh melihat status service apa pun,
tetapi tetap mengikuti kebijakan autentikasi normal.

\textbf{Langkah 2}: Verifikasi aturan yang aktif dan uji hasilnya.

\begin{lstlisting}[language=bash, caption={Verifikasi hak sudo dan log}]
sudo -l -U userA
sudo grep "userA" /var/log/auth.log | tail -10
\end{lstlisting}

\cmd{sudo -l -U userA} dipakai untuk mengecek aturan yang aktif dari sudut pandang
akun \texttt{userA}. Log di \file{/var/log/auth.log} membantu memverifikasi bahwa
pemakaian sudo benar-benar tercatat.

\textbf{Analisis}

\begin{enumerate}
    \item Mengapa aturan disimpan di \dir{/etc/sudoers.d/}, bukan langsung di
        \file{/etc/sudoers}?
    \item Mana perintah yang bisa dijalankan tanpa password, dan mana yang masih perlu
        autentikasi?
    \item Informasi apa saja yang dicatat di log sudo?
\end{enumerate}

\textbf{Tantangan}

Tambahkan satu aturan baru agar \texttt{userA} boleh menjalankan
\cmd{/bin/systemctl restart ssh} tetapi tidak boleh menjalankan \cmd{reboot}.

\section{Disk Quota}
\label{sec:disk-quota}
%% ========================================================================

\textbf{Penjelasan Konsep}

Quota membatasi penggunaan ruang disk dan/atau jumlah file milik user atau group.
Fungsinya sederhana: mencegah satu pengguna menghabiskan seluruh sumber daya storage.

\subsection{Konsep Disk Quota}
\label{sec:disk-quota-konsep}

Ada dua dimensi quota:

\begin{description}
    \item[Block quota] membatasi total ruang disk yang dipakai. Di Linux, tools quota
        umumnya memakai satuan kilobyte.
    \item[Inode quota] membatasi jumlah file/direktori, terlepas dari ukurannya.
\end{description}

Selain itu, ada tiga istilah kebijakan yang wajib dipahami:

\begin{table}[htbp]
    \centering
    \caption{Jenis limit pada disk quota}
    \label{tab:quota-limits}
    \begin{tblr}{
        colspec = {lQ[2cm,l]X[l]},
        width = \linewidth,
        hlines,
        vlines,
        row{1} = {font=\bfseries},
        cells = {font=\small}
    }
    \textbf{Jenis} & \textbf{Berlaku pada} & \textbf{Makna} \\
    Soft limit & Blok dan inode & Boleh dilampaui sementara selama grace period \\
    Hard limit & Blok dan inode & Tidak boleh dilampaui sama sekali \\
    Grace period & Soft limit & Waktu toleransi sebelum soft limit diperlakukan seperti hard limit \\
    \end{tblr}
\end{table}

\begin{notebox}
Inode quota penting saat pengguna membuat sangat banyak file kecil. Ruang disk mungkin
masih ada, tetapi inode filesystem bisa habis lebih dulu.
\end{notebox}

\textbf{Perintah yang Digunakan}

\begin{itemize}
    \item \texttt{quotacheck}: membuat atau memperbarui database quota.
    \item \texttt{quotaon}/\texttt{quotaoff}: mengaktifkan atau menonaktifkan enforcement.
    \item \texttt{edquota}: mengedit limit quota secara interaktif.
    \item \texttt{setquota}: menetapkan limit quota dari command line.
    \item \texttt{quota}, \texttt{repquota}: melihat penggunaan quota.
\end{itemize}

\subsection{Mengaktifkan Quota}

Workflow aktivasi quota biasanya terdiri dari empat langkah:

\begin{enumerate}
    \item instal paket quota,
    \item aktifkan opsi \texttt{usrquota} dan/atau \texttt{grpquota} di filesystem,
    \item buat database quota dengan \cmd{quotacheck},
    \item aktifkan enforcement dengan \cmd{quotaon}.
\end{enumerate}

\begin{lstlisting}[language=bash, caption={Workflow dasar aktivasi quota}]
sudo apt install -y quota quotatool

# /etc/fstab
# UUID=abc123 /home ext4 defaults,usrquota,grpquota 0 2

sudo mount -o remount /home
sudo quotacheck -cugm /home
sudo quotaon -v /home
sudo repquota -s /home
\end{lstlisting}

\subsection{Menetapkan dan Melihat Quota}

Perintah yang paling penting adalah:

\begin{lstlisting}[language=bash, caption={Perintah inti pengelolaan quota}]
# editor interaktif
sudo edquota -u alice
sudo edquota -g developers

# tanpa editor
sudo setquota -u alice 1048576 1572864 10000 15000 /home

# lihat status
quota -s
sudo quota -u alice
sudo repquota -s /home

# grace period
sudo edquota -t
\end{lstlisting}

Makna argumen pada \cmd{setquota -u alice 1048576 1572864 10000 15000 /home}:

\begin{itemize}
    \item soft block = 1~GB
    \item hard block = 1,5~GB
    \item soft inode = 10.000
    \item hard inode = 15.000
\end{itemize}

\subsection{Operasi Lanjutan yang Perlu Dikenal}

\begin{lstlisting}[language=bash, caption={Operasi quota lanjutan}]
# salin quota dari satu user ke user lain
sudo edquota -p alice bob charlie

# kirim peringatan email
sudo warnquota

# matikan quota
sudo quotaoff -v /home
\end{lstlisting}

\subsection*{Praktikum 9.5 --- Disk Quota}

\textbf{Tujuan}: memahami alur quota secara aman pada loopback filesystem tanpa
mengubah filesystem utama.

\textbf{Langkah 1}: Buat image filesystem kecil dan mount dengan opsi quota.

\begin{lstlisting}[language=bash, caption={Menyiapkan filesystem uji quota}]
sudo dd if=/dev/zero of=/tmp/quota-test.img bs=1M count=100
sudo mkfs.ext4 /tmp/quota-test.img
sudo mkdir -p /mnt/quota-test
sudo mount -o loop,usrquota,grpquota /tmp/quota-test.img /mnt/quota-test
\end{lstlisting}

Image file dipakai agar praktikum aman: Anda tidak perlu memodifikasi filesystem utama
seperti \dir{/home}. Opsi \texttt{usrquota,grpquota} mengaktifkan dua jenis quota sekaligus.

\textbf{Langkah 2}: Buat database quota dan aktifkan enforcement.

\begin{lstlisting}[language=bash, caption={Inisialisasi dan aktivasi quota}]
sudo quotacheck -cug /mnt/quota-test
sudo quotaon -v /mnt/quota-test
sudo repquota /mnt/quota-test
\end{lstlisting}

\cmd{quotacheck -cug} membuat database user dan group quota. Setelah itu,
\cmd{quotaon} mengaktifkan enforcement, dan \cmd{repquota} menampilkan laporan awal.

\textbf{Langkah 3}: Tetapkan quota untuk user uji dan amati hasilnya.

\begin{lstlisting}[language=bash, caption={Menetapkan quota untuk userA}]
sudo edquota -u userA
# contoh: soft block 5120, hard block 10240
sudo repquota /mnt/quota-test
\end{lstlisting}

Nilai di atas memakai satuan KB. Jadi \texttt{5120} berarti sekitar 5 MB, dan
\texttt{10240} berarti sekitar 10 MB.

\textbf{Langkah 4}: Bersihkan lingkungan uji setelah selesai.

\begin{lstlisting}[language=bash, caption={Pembersihan quota test}]
sudo quotaoff /mnt/quota-test
sudo umount /mnt/quota-test
sudo rm /tmp/quota-test.img
\end{lstlisting}

\textbf{Analisis}

\begin{enumerate}
    \item Apa perbedaan soft limit dan hard limit saat quota mulai terlampaui?
    \item Mengapa praktikum ini memakai loopback filesystem, bukan langsung \dir{/home}?
    \item Dari output \cmd{repquota}, informasi apa yang menunjukkan quota sudah aktif?
\end{enumerate}

\textbf{Tantangan}

Coba atur quota baru untuk \texttt{userA} dengan batas inode yang sangat kecil,
kemudian jelaskan kapan pembatasan inode lebih penting daripada pembatasan block.

\section{Rangkuman}
\label{sec:file-user-summary}
%% ========================================================================

Bab ini membahas lima kelompok konsep inti:

\begin{description}
    \item[Permissions] owner, group, others; izin \texttt{rwx}; \cmd{chmod},
        \cmd{chown}, \cmd{chgrp}; special bits; dan umask.
    \item[ACL] perluasan permission Unix untuk kebutuhan akses granular per-user atau
        per-group, termasuk default ACL direktori dan mask.
    \item[User/Group] identitas pengguna disimpan di \file{/etc/passwd},
        \file{/etc/shadow}, dan \file{/etc/group}; dikelola dengan keluarga perintah
        \cmd{useradd}, \cmd{usermod}, \cmd{userdel}, \cmd{groupadd}, dan \cmd{gpasswd}.
    \item[sudo dan su] \cmd{sudo} adalah mekanisme delegasi hak administratif yang
        lebih aman dan lebih dapat diaudit dibanding \cmd{su}.
    \item[Disk Quota] pembatasan blok dan inode melalui soft limit, hard limit,
        grace period, serta perintah seperti \cmd{edquota}, \cmd{setquota}, dan
        \cmd{repquota}.
\end{description}
