\chapter{Manajemen Memori dan System Call}
\label{ch:memory-and-syscalls}

Bayangkan meja kerja kamu. Di atas meja tersimpan dokumen yang sedang aktif digunakan
--- inilah yang diibaratkan sebagai \textbf{RAM}. Saat meja mulai penuh, beberapa
dokumen dipindahkan ke laci agar ada ruang baru --- inilah yang diibaratkan sebagai
\textbf{swap}. Jika semua dokumen tersimpan di laci dan kamu terus bolak-balik
mengambilnya, pekerjaan menjadi lambat. Itulah gambaran sederhana bagaimana Linux
mengelola memori. Di bab ini kita juga akan mempelajari \textbf{system call} ---
mekanisme yang digunakan program untuk meminta layanan dari kernel, dan memanfaatkan
keterampilan Bash dari Bab~9 untuk membangun script monitoring yang nyata.

\textbf{Yang Akan Kamu Pelajari}

Setelah menyelesaikan bab ini, kamu akan mampu:

\begin{enumerate}
    \item memahami arsitektur memori virtual sebuah proses Linux;
    \item mengamati dan menginterpretasi aktivitas paging dengan \texttt{vmstat};
    \item membuat dan mengonfigurasi swap space beserta parameter swappiness;
    \item mengidentifikasi proses dengan penggunaan memori terbesar;
    \item menulis script Bash untuk monitoring memori otomatis;
    \item mengamati dan menganalisis system call menggunakan \texttt{strace}.
\end{enumerate}

\begin{notebox}
Seluruh praktikum dijalankan sebagai pengguna biasa kecuali perintah yang secara
eksplisit menggunakan \texttt{sudo}. Buat direktori kerja terlebih dahulu:
\begin{lstlisting}
mkdir -p ~/praktikum-os/week10-memory
\end{lstlisting}
\end{notebox}

\section{Arsitektur Memori di Linux}

Setiap program yang berjalan di Linux mendapatkan \textit{ruang alamat virtual}
sendiri. Artinya, setiap program seolah-olah memiliki memori pribadi yang tidak dapat
diganggu program lain --- kernel yang mengatur pemetaan antara alamat virtual tersebut
dengan memori fisik (RAM). Ruang alamat virtual sebuah proses dibagi menjadi beberapa
area seperti terlihat pada \cref{fig:memory-layout}: \textbf{Text Segment} menyimpan
instruksi kode (read-only), \textbf{Data Segment} menyimpan variabel global, \textbf{Heap}
tumbuh ke atas untuk alokasi dinamis (\texttt{malloc()}), \textbf{Stack} tumbuh ke
bawah untuk variabel lokal dan return address, serta \textbf{Kernel Space} yang hanya
dapat diakses kernel.

Isolasi antar proses menjamin stabilitas sistem. Jika satu program crash, kerusakan
hanya berdampak pada proses tersebut --- proses lain tetap berjalan normal.
\end{notebox}

\subsection*{Praktikum 10.1 Melihat Penggunaan Memori}

Jalankan \texttt{free -h} untuk melihat ringkasan RAM dan swap, lalu lihat detail
memori dari kernel:

\begin{lstlisting}[caption={Ringkasan dan detail memori}]
free -h
cat /proc/meminfo | head -n 20
\end{lstlisting}

Output \texttt{free -h} menampilkan baris \texttt{Mem} (RAM) dan \texttt{Swap}.
Kolom kunci: \texttt{total} (total RAM), \texttt{used} (terpakai), \texttt{free}
(benar-benar kosong), \texttt{available} (tersedia untuk aplikasi baru --- gunakan
nilai ini, bukan \texttt{free}), dan \texttt{buff/cache} (cache file yang dibebaskan
otomatis jika dibutuhkan).

\textit{Amati:} Hitung \texttt{available / total × 100\%}. Di bawah 10\% berarti
sistem mulai kekurangan memori. Jika kolom \texttt{used} pada baris \texttt{Swap}
lebih dari 0, kernel sudah pernah memindahkan data ke disk.

\begin{tipbox}
Jangan khawatir jika \texttt{used} tampak besar. Linux sengaja menggunakan RAM
kosong sebagai cache untuk mempercepat akses file. Fokus pada \texttt{available}.
\end{tipbox}

\begin{challengebox}
Server aplikasi terasa lambat saat banyak pengguna aktif. Gunakan \texttt{free -h}
dan \texttt{top} untuk menyelidiki kondisi memori. Di dalam \texttt{top}, tekan
\keystroke{M} untuk mengurutkan berdasarkan memori. Catat: nilai \texttt{available},
apakah \texttt{Swap used} lebih dari 0, dan nama proses dengan \texttt{\%MEM}
terbesar. Tulis analisis singkat: apakah server kemungkinan kekurangan memori?
\end{challengebox}

\section{Manajemen Memori Virtual}

Bayangkan sebuah perpustakaan besar. Kamu hanya bisa meletakkan beberapa buku di
meja baca (RAM), sementara sisanya di rak (disk/swap). Saat butuh buku dari rak,
kamu ambil dan kembalikan buku lain. Itulah cara kerja \textit{memori virtual}
dan \textit{paging}.

Data dibagi dalam blok berukuran tetap yang disebut \textbf{page}. Kernel secara
otomatis memindahkan page yang tidak aktif ke swap (\textit{swap out}) dan memuatnya
kembali saat dibutuhkan (\textit{swap in}), seperti digambarkan pada
\cref{fig:virtual-memory}. Perintah \texttt{vmstat 1 5} menampilkan statistik memori
virtual setiap 1 detik selama 5 sampel --- kolom \texttt{si} (swap in) dan \texttt{so}
(swap out) adalah indikator utama aktivitas paging.

\subsection*{Praktikum 10.2 Mengamati Aktivitas Paging}

\begin{lstlisting}[caption={Statistik memori virtual}]
vmstat 1 5
\end{lstlisting}

Temukan kolom \texttt{swap}: sub-kolom \texttt{si} (KB/detik dari disk ke RAM) dan
\texttt{so} (KB/detik dari RAM ke disk).

\textit{Amati:} Pada sistem normal dengan RAM cukup, \texttt{si} dan \texttt{so}
selalu 0. Jika keduanya terus-menerus lebih dari 0, sistem dalam kondisi
\textit{memory pressure} serius --- akses disk jauh lebih lambat dari RAM sehingga
performa turun drastis.

\begin{warningbox}
Nilai \texttt{si} dan \texttt{so} yang tinggi terus-menerus menandakan sistem butuh
lebih banyak RAM. Solusi: tambah RAM, kurangi proses, atau optimalkan aplikasi.
\end{warningbox}

\begin{challengebox}
Gunakan teknik loop dari Bab~9 untuk mencatat nilai \texttt{si} dan \texttt{so}
setiap 5 detik selama 30 detik, simpan ke file \texttt{paging-log.txt}:
\begin{lstlisting}
for i in $(seq 1 6); do
    vmstat 1 2 | tail -1 >> paging-log.txt
    sleep 5
done
cat paging-log.txt
\end{lstlisting}
Apakah nilai \texttt{si}/\texttt{so} berubah selama pemantauan? Apa kesimpulanmu
tentang kondisi memori sistem?
\end{challengebox}

\section{Konfigurasi Swap Space}

Swap space adalah area di disk yang berfungsi sebagai perpanjangan RAM. Swap mencegah
sistem crash saat RAM penuh, tetapi karena berada di disk, aksesnya jauh lebih lambat.
Swap adalah \textit{jaring pengaman}, bukan pengganti RAM.

Parameter \texttt{swappiness} (nilai 0--100) mengatur agresivitas kernel dalam
menggunakan swap. Nilai tinggi (60--100, default Linux = 60) berarti kernel cepat
memindahkan data ke swap meski RAM masih tersedia. Nilai rendah (10--20) berarti
kernel lebih mengutamakan RAM dan hanya menggunakan swap jika benar-benar terpaksa
--- disarankan untuk server aplikasi.

\subsection*{Praktikum 10.3 Membuat dan Mengonfigurasi Swap File}

\textbf{Langkah 1}: Buat file 512~MB, amankan permission-nya, format sebagai swap,
lalu aktifkan.

\begin{lstlisting}[caption={Membuat dan mengaktifkan swap}]
sudo fallocate -l 512M /swapfile-week10
sudo chmod 600 /swapfile-week10
sudo mkswap /swapfile-week10
sudo swapon /swapfile-week10
\end{lstlisting}

\begin{warningbox}
\texttt{chmod 600} \textbf{wajib} dilakukan sebelum \texttt{mkswap}. File swap dapat
berisi potongan data sensitif dari memori program. Permission terbuka (\texttt{644})
membuat pengguna lain bisa membaca isi memori tersebut.
\end{warningbox}

\textbf{Langkah 2}: Verifikasi swap aktif, lalu periksa dan ubah swappiness.

\begin{lstlisting}[caption={Verifikasi dan atur swappiness}]
swapon --show
free -h
cat /proc/sys/vm/swappiness
sudo sysctl vm.swappiness=10
cat /proc/sys/vm/swappiness
\end{lstlisting}

\textit{Amati:} Entri \texttt{/swapfile-week10} harus muncul di \texttt{swapon --show}
dan nilai \texttt{total} pada baris \texttt{Swap} di \texttt{free -h} bertambah 512~MB.
Konfirmasi nilai swappiness berubah dari 60 ke 10 pada output \texttt{cat} kedua.

\begin{notebox}
Perubahan \texttt{sysctl} bersifat sementara dan hilang setelah reboot. Untuk
konfigurasi permanen, tambahkan \texttt{vm.swappiness=10} ke \texttt{/etc/sysctl.conf}.

Bersihkan setelah praktikum:
\begin{lstlisting}
sudo swapoff /swapfile-week10
sudo rm /swapfile-week10
\end{lstlisting}
\end{notebox}

\begin{challengebox}
Buat swap file kedua berukuran 128~MB, aktifkan, lalu coba tiga nilai swappiness
berbeda (1, 60, 100) --- catat perbedaan yang terlihat di \texttt{swapon --show}
dan \texttt{free -h} setiap kali. Jelaskan: kapan nilai swappiness 1 lebih baik
daripada 100 untuk sebuah web server? Bersihkan kedua swap file setelah selesai.
\end{challengebox}

\section{Pemantauan Penggunaan Memori}

Pemantauan memori membantu mendeteksi masalah sebelum berdampak ke pengguna. Ada
dua pendekatan: \textbf{real-time} dengan \texttt{top} (perubahan dinamis saat ini)
dan \textbf{snapshot} dengan \texttt{ps aux} (daftar proses pada satu titik waktu,
cocok untuk laporan). Kolom penting pada \texttt{ps aux}: \texttt{\%MEM} (persentase
RAM), \texttt{RSS} (RAM fisik benar-benar terpakai saat ini dalam KB), dan
\texttt{VSZ} (total memori virtual yang dialokasikan, selalu lebih besar dari RSS).

\subsection*{Praktikum 10.4 Monitor Memori dengan Script}

\textbf{Langkah 1}: Ambil snapshot proses dengan penggunaan memori terbesar.

\begin{lstlisting}[caption={Proses dengan memori terbesar}]
ps aux --sort=-%mem | head
\end{lstlisting}

\textit{Amati:} Proses di baris kedua (setelah header) adalah pengguna memori
terbesar saat itu. Konversikan \texttt{RSS} dari KB ke MB (bagi 1024) untuk
memahami berapa RAM fisik yang benar-benar dipakai.

\textbf{Langkah 2}: Buat script monitoring otomatis yang menerapkan konsep Bab~9
(variabel, kondisi \texttt{if}, dan parsing dengan \texttt{awk}).

\begin{lstlisting}[caption={Pindah ke direktori dan buka nano}]
cd ~/praktikum-os/week10-memory
nano monitor-memori.sh
\end{lstlisting}

\begin{lstlisting}[caption={Isi file monitor-memori.sh}]
#!/bin/bash
set -euo pipefail

THRESHOLD=20

echo "=== Monitor Memori ==="
date
echo

free -h
echo

AVAIL=$(free | awk '/Mem/ {printf "%d", $7/$2*100}')
if [ "$AVAIL" -lt "$THRESHOLD" ]; then
    echo "PERINGATAN: Memori tersedia hanya ${AVAIL}%!"
else
    echo "Status: Memori tersedia ${AVAIL}% (normal)"
fi
echo

echo "--- 5 Proses Memori Tertinggi ---"
ps aux --sort=-%mem | head -n 6 | tail -n 5
\end{lstlisting}

\begin{notebox}
Simpan: \keystroke{Ctrl+O} $\to$ \keystroke{Enter} $\to$ keluar: \keystroke{Ctrl+X}.
\end{notebox}

\begin{lstlisting}[caption={Jalankan script monitor}]
chmod +x monitor-memori.sh
bash monitor-memori.sh
\end{lstlisting}

\textit{Amati:} Perintah \texttt{awk '/Mem/ \{printf "\%d", \$7/\$2*100\}'} mengambil
kolom ke-7 (available) dibagi kolom ke-2 (total) dari baris \texttt{Mem}, lalu dikali
100 menjadi persentase bilangan bulat. Ubah \texttt{THRESHOLD} ke \texttt{90} dan
jalankan ulang --- apakah output berubah? Mengapa?

\begin{challengebox}
Kembangkan \texttt{monitor-memori.sh} agar setiap kali dijalankan menyimpan log
ke file bernama \texttt{memori-YYYYMMDD-HHMMSS.txt} menggunakan \texttt{date}
(teknik dari Bab~9) dan juga tetap menampilkan output ke layar dengan \texttt{tee}:
\begin{lstlisting}
LOGFILE="memori-$(date +%Y%m%d-%H%M%S).txt"
# ... isi script ... | tee "$LOGFILE"
\end{lstlisting}
Jalankan dua kali dan verifikasi dua file log terpisah terbuat.
\end{challengebox}

\section{System Call dan Interaksi User-Kernel}

Bayangkan sebuah restoran. Kamu (program) tidak bisa langsung masuk ke dapur (kernel)
untuk memasak sendiri --- kamu harus memesan melalui pramusaji (system call).
Pramusaji meneruskan pesanan ke dapur, memastikan pesanan valid, dan membawa hasilnya
kembali ke meja kamu.

Itulah cara kerja system call: mekanisme bagi program di \textit{user space} untuk
meminta layanan dari kernel. Program tidak dapat langsung mengakses hardware,
filesystem, atau sumber daya kernel --- semua permintaan harus melalui system call.
Alur lengkapnya ditunjukkan pada \cref{fig:syscall-flow}.

\begin{figure}[H]
\centering
\begin{tikzpicture}[font=\small, >=latex,
    ub/.style={draw, fill=blue!12, rounded corners=3pt,
               minimum width=3.8cm, minimum height=0.8cm, align=center},
    kb/.style={draw, fill=orange!18, rounded corners=3pt,
               minimum width=3.8cm, minimum height=0.8cm, align=center}
]
    \node[font=\small\bfseries, blue!70!black]   at (2.0, 5.8) {User Space};
    \node[font=\small\bfseries, orange!70!black] at (7.5, 5.8) {Kernel Space};
    \draw[dashed, thick, gray!60] (4.75, 0.0) -- (4.75, 5.5);
    \node[ub] (app) at (2.0, 5.0) {\texttt{printf("Hello")}};
    \node[ub] (lib) at (2.0, 3.7) {library C:\\\texttt{write(1,"Hello",5)}};
    \node[ub] (fin) at (2.0, 0.5) {program lanjutkan};
    \node[kb] (val) at (7.5, 3.7) {validasi parameter};
    \node[kb] (exe) at (7.5, 2.4) {kirim ke terminal};
    \node[kb] (ret) at (7.5, 1.1) {kembalikan nilai = 5};
    \draw[->] (app) -- (lib) node[midway, right, font=\footnotesize] {panggil};
    \draw[->, thick, red!60!black] (lib) -- (val)
        node[midway, above, font=\footnotesize] {system call};
    \draw[->] (val) -- (exe);
    \draw[->] (exe) -- (ret);
    \draw[->, thick, blue!60!black] (ret) -- (fin)

\end{tikzpicture}
\caption{Alur system call \texttt{printf}: program user meminta layanan kernel melalui
antarmuka yang terkontrol, bukan langsung ke hardware.}
\label{fig:syscall-flow}
\end{figure}

System call dikelompokkan berdasarkan fungsinya: \textbf{Manajemen Proses}
(\texttt{fork}, \texttt{exec}, \texttt{exit}), \textbf{Manajemen File}
(\texttt{open}, \texttt{read}, \texttt{write}, \texttt{close}),
\textbf{Manajemen Memori} (\texttt{mmap}, \texttt{brk}), \textbf{Komunikasi}
(\texttt{pipe}, \texttt{socket}), dan \textbf{Informasi Sistem}
(\texttt{getpid}, \texttt{uname}). Perintah \texttt{strace} memungkinkan kita
melihat setiap system call yang dipanggil suatu perintah, beserta argumen dan
nilai kembaliannya.

\subsection*{Praktikum 10.5 Mengamati System Call dengan strace}

\textbf{Langkah 1}: Simulasikan kegagalan akses file karena permission.

\begin{lstlisting}[caption={Simulasi permission error}]
mkdir -p ~/praktikum-os/week10-memory/syscall-case
cd ~/praktikum-os/week10-memory/syscall-case
echo "PORT=8080" > app.conf
chmod 000 app.conf
cat app.conf
\end{lstlisting}

Output \texttt{cat: app.conf: Permission denied} terjadi karena system call
\texttt{openat()} gagal --- kernel menolak permintaan membuka file karena tidak ada
bit izin baca (\texttt{r}). Kembalikan permission dengan \texttt{chmod 644 app.conf}.

\textbf{Langkah 2}: Amati semua system call dari perintah \texttt{ls}.

\begin{lstlisting}[caption={Detail dan ringkasan system call}]
strace ls 2>&1 | head -n 30
strace -c ls
\end{lstlisting}

Setiap baris mengikuti format \texttt{namasyscall(argumen) = nilai\_kembali}.
Contoh: \texttt{openat(AT\_FDCWD, "/etc/ld.so.cache", O\_RDONLY) = 3} artinya
membuka file untuk dibaca, berhasil (file descriptor = 3). Nilai \texttt{-1 ENOENT}
berarti gagal karena file tidak ditemukan.

\textit{Amati:} Dari ringkasan \texttt{strace -c}, system call mana yang paling
sering dipanggil? Apakah ada baris dengan \texttt{errors} lebih dari 0? Apakah
program tetap berjalan normal meskipun ada kegagalan tersebut?

\begin{tipbox}
Gunakan \texttt{strace -c} untuk gambaran umum cepat. Gunakan \texttt{strace} tanpa
\texttt{-c} untuk melihat urutan dan argumen lengkap setiap system call saat
mendiagnosis masalah konkret.
\end{tipbox}

\begin{challengebox}
Gunakan \texttt{strace} dengan filter khusus untuk hanya melihat system call
\texttt{openat}:
\begin{lstlisting}
strace -e trace=openat cat /etc/hostname 2>&1
\end{lstlisting}
Hitung berapa file yang dibuka. Identifikasi mana yang berhasil (nilai positif)
dan mana yang gagal (nilai \texttt{-1}). Mengapa \texttt{cat} membuka lebih
dari satu file hanya untuk menampilkan \texttt{/etc/hostname}?
\end{challengebox}

\section{Rangkuman}

Dalam bab ini, kamu telah mempelajari:

\begin{itemize}
    \item \textbf{Arsitektur memori virtual}: setiap proses memiliki ruang alamat virtual
          sendiri yang dipetakan kernel ke RAM fisik melalui page table.
    \item \textbf{Aktivitas paging}: \cmd{vmstat} menampilkan kolom \texttt{si}/\texttt{so}
          untuk swap-in dan swap-out; angka tinggi menandakan tekanan memori.
    \item \textbf{Konfigurasi swap}: swap file dibuat dengan \cmd{fallocate}, diformat
          \cmd{mkswap}, dan diaktifkan \cmd{swapon}; nilai \texttt{vm.swappiness} mengatur
          agresivitas penggunaan swap.
    \item \textbf{Pemantauan memori}: \cmd{free -h}, \cmd{top}/\cmd{htop}, dan
          \cmd{/proc/meminfo} memberi laporan penggunaan RAM dan swap dari berbagai sudut;
          script Bash dapat mengotomatiskan pemantauan berkala.
    \item \textbf{Script monitoring}: teknik Bash dari Bab~9 --- fungsi, loop, dan
          \cmd{tee} --- digabungkan untuk membangun \texttt{monitor-memori.sh} yang
          mencatat log bertanggal secara otomatis.
    \item \textbf{System call}: program berinteraksi dengan kernel melalui system call;
          \cmd{strace} memperlihatkan urutan panggilan tersebut sehingga kamu dapat
          menganalisis perilaku dan kesalahan program.
\end{itemize}

\subsubsection{Tugas 10.5 Studi Kasus Diagnosa Server Lambat}

Buat script diagnosa yang menggabungkan semua pemeriksaan dari bab ini menggunakan
fungsi Bash dari Bab~9.

\begin{lstlisting}[caption={Buka file dengan nano}]
nano ~/praktikum-os/week10-memory/diagnosa-server.sh
\end{lstlisting}

\begin{longlisting}[language=bash, caption={Isi file diagnosa-server.sh}]
#!/bin/bash
set -euo pipefail

LAPORAN="diagnosa-server-lambat.txt"
WARN_MEM=false
WARN_SWAP=0

cek_memori() {
    echo "--- Kondisi Memori ---"
    free -h
    echo
    AVAIL_PCT=$(free | awk '/Mem/ {printf "%d", $7/$2*100}')
    if [ "$AVAIL_PCT" -lt 20 ]; then
        echo "PERINGATAN: Memori tersedia hanya ${AVAIL_PCT}%"
        WARN_MEM=true
    fi
}

cek_swap() {
    echo "--- Penggunaan Swap ---"
    swapon --show 2>/dev/null || echo "Tidak ada swap aktif"
    echo
    WARN_SWAP=$(free | awk '/Swap/ {print $3}')
    if [ "$WARN_SWAP" -gt 0 ]; then
        echo "INFO: Swap digunakan (${WARN_SWAP} kB)"
    fi
}

cek_proses() {
    echo "--- 10 Proses Memori Tertinggi ---"
    ps aux --sort=-%mem | head -n 11
    echo
}

cek_paging() {
    echo "--- Aktivitas Paging (5 sampel) ---"
    vmstat 1 5
    echo
}

ringkasan() {
    echo "=== RINGKASAN ==="
    if [ "$WARN_MEM" = true ]; then
        echo "- Memori: KRITIS - perlu tindakan segera"
    else
        echo "- Memori: normal"
    fi
    if [ "$WARN_SWAP" -gt 0 ]; then
        echo "- Swap: aktif - pantau aktivitas paging"
    else
        echo "- Swap: tidak digunakan"
    fi
}

{
    echo "=== LAPORAN DIAGNOSA SERVER ==="
    date
    echo

    cek_memori
    cek_swap
    cek_proses
    cek_paging
    ringkasan
} | tee "$LAPORAN"

echo
echo "Laporan disimpan ke: $LAPORAN"
\end{longlisting}

\begin{notebox}
Simpan: \keystroke{Ctrl+O} $\to$ \keystroke{Enter} $\to$ keluar: \keystroke{Ctrl+X}.
\end{notebox}

\begin{lstlisting}[caption={Jalankan script diagnosa}]
chmod +x ~/praktikum-os/week10-memory/diagnosa-server.sh
bash diagnosa-server.sh
\end{lstlisting}

Jawab: (1) Jelaskan peran masing-masing fungsi dan mengapa diagnosa dipecah menjadi
fungsi terpisah. (2) Berdasarkan bagian \texttt{RINGKASAN}, apakah kondisi sistem
normal atau kritis? (3) Mengapa script menggunakan \texttt{tee "\$LAPORAN"} bukan
redirection biasa \texttt{> "\$LAPORAN"}? (4) Apakah ada aktivitas \texttt{si} atau
\texttt{so} dari \texttt{cek\_paging}? Apa implikasinya?
