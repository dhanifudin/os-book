\chapter{Manajemen Aplikasi}
\label{ch:application-management}

Bayangkan kamu baru pindah ke kota baru dan ingin melengkapi dapur apartemenmu.
Ada dua cara: pergi ke toko swalayan yang sudah mengatur semua kebutuhan di rak
yang berlabel rapi, atau berkeliling dari toko ke toko secara manual mencari
barang satu per satu. Di Linux, \cmd{apt} berperan seperti swalayan modern itu.
Kamu cukup menyebut nama aplikasi, dan \cmd{apt} akan mengunduh, memeriksa
keaslian, memasang semua bagian yang dibutuhkan, dan mendaftarkan semuanya agar
mudah dihapus kapan saja.

Di balik layanan \cmd{apt} yang nyaman itu, ada lapisan yang lebih mendasar bernama
\cmd{dpkg}. Jika \cmd{apt} adalah kasir swalayan yang mengurus segalanya, maka
\cmd{dpkg} adalah petugas gudang yang benar-benar meletakkan barang ke rak. Ada
saat-saat ketika kamu perlu berbicara langsung dengan petugas gudang itu, misalnya
saat menginstal file \texttt{.deb} yang kamu unduh sendiri dari situs vendor.

Bab ini juga membahas situasi ketika aplikasi yang kamu butuhkan belum tersedia
di toko mana pun. Dalam kasus itu, kamu perlu merakit sendiri dari bahan mentah,
yang di Linux berarti mengompilasi dari \emph{source code}. Dan untuk aplikasi
 yang membutuhkan lingkungan terisolasi agar tidak bertabrakan dengan sistem,
 teknologi container seperti Docker dan Podman menawarkan cara membungkus
 aplikasi beserta semua perlengkapannya.

\textbf{Yang Akan Kamu Pelajari}

Setelah menyelesaikan bab ini, kamu akan mampu:

\begin{enumerate}
    \item menginstal, memperbarui, dan menghapus paket menggunakan \cmd{apt} dan
        \cmd{dpkg} secara tepat;
    \item menambahkan repositori pihak ketiga dengan metode GPG key yang aman;
    \item mengompilasi program sederhana dari source code menggunakan pola
        \cmd{./configure}, \cmd{make}, dan \cmd{make install};
    \item membangun dan menjalankan aplikasi di dalam container, dengan Docker
        sebagai contoh utama dan Podman sebagai alternatif yang sepadan;
    \item memantau performa aplikasi yang sedang berjalan menggunakan \cmd{top},
        \cmd{lsof}, dan \cmd{ss}.
\end{enumerate}

\begin{notebox}
Seluruh praktikum pada bab ini dijalankan pada direktori \dir{~/lab-os/week13-apps/}.
\begin{lstlisting}[language=bash]
mkdir -p ~/lab-os/week13-apps
cd ~/lab-os/week13-apps
\end{lstlisting}
\end{notebox}

\section{Manajemen Paket dengan apt}
\label{sec:apt-package-management}
%% ========================================================================

Sistem manajemen paket di Ubuntu dibangun dari dua lapisan yang bekerja sama.
\cmd{dpkg} adalah lapisan bawah: alat tingkat rendah yang langsung membongkar
dan memasang file \texttt{.deb} ke tempatnya masing-masing di filesystem. Namun
\cmd{dpkg} tidak peduli apakah semua bahan pendukung sudah tersedia sebelum
pemasangan dilakukan.

\cmd{apt} mengisi celah itu. Sebelum memasang paket apa pun, \cmd{apt}
membaca daftar paket dari server repositori, memeriksa semua dependensi yang
dibutuhkan, mengunduh semuanya dalam urutan yang benar, kemudian menyerahkan
pekerjaan pemasangan fisik ke \cmd{dpkg}. Dalam praktik sehari-hari, kamu
hampir selalu berinteraksi dengan \cmd{apt}. \cmd{dpkg} baru digunakan
langsung ketika menginstal file \texttt{.deb} yang diunduh manual, atau
saat mengaudit apa yang sudah terinstal.

Sebelum menginstal atau memperbarui apa pun, \cmd{apt} perlu menyegarkan
daftar paket yang dimilikinya. Daftar ini adalah katalog yang berisi versi
terbaru setiap paket dari semua repositori yang dikonfigurasi. Tanpa pembaruan
daftar, \cmd{apt} mungkin masih merujuk ke informasi yang sudah usang.

\begin{lstlisting}[language=bash, caption={Memperbarui daftar paket dan sistem}]
sudo apt update
sudo apt upgrade
sudo apt full-upgrade
\end{lstlisting}

Perintah \cmd{apt update} mengunduh metadata terbaru dari semua repositori,
bukan aplikasinya. \cmd{apt upgrade} kemudian memperbarui semua paket yang
sudah terinstal ke versi terbaru, tetapi tidak akan menghapus paket mana pun
dalam prosesnya. \cmd{apt full-upgrade} lebih agresif: ia boleh menghapus
paket lama jika diperlukan untuk menyelesaikan konflik dependensi saat ada
pembaruan besar.

Untuk memasang paket baru, cukup sebutkan namanya. \cmd{apt} akan mencari
semua yang dibutuhkan dan meminta konfirmasi sebelum mengunduh.

\begin{lstlisting}[language=bash, caption={Instalasi dan penghapusan paket}]
sudo apt install tree
sudo apt install curl wget git
sudo apt remove tree
sudo apt purge tree
sudo apt autoremove
\end{lstlisting}

Perbedaan antara \cmd{remove} dan \cmd{purge} penting untuk dipahami.
\cmd{remove} menghapus binary dan file program, tetapi menyisakan file
konfigurasi di \dir{/etc/}. Ini berguna jika kamu ingin menginstal ulang
nanti dengan konfigurasi yang sama. \cmd{purge} menghapus semuanya termasuk
konfigurasi. Gunakan \cmd{purge} saat kamu benar-benar ingin memulai bersih.
Setelah penghapusan, \cmd{autoremove} membersihkan paket dependensi yang dulu
dipasang otomatis tetapi kini tidak lagi dibutuhkan siapa pun.

Mencari dan memeriksa informasi paket sebelum menginstalnya adalah kebiasaan
yang baik. \cmd{apt} menyediakan beberapa cara untuk itu.

\begin{lstlisting}[language=bash, caption={Mencari dan memeriksa informasi paket}]
apt search tree
apt search --names-only tree
apt show tree
apt list --installed
apt list --installed | grep python
dpkg -l
dpkg -l | grep "^ii"
dpkg -L tree
dpkg -S /bin/ls
\end{lstlisting}

\cmd{apt search} mencari berdasarkan nama dan deskripsi. Opsi
\texttt{--names-only} membatasi pencarian hanya pada nama paket sehingga
hasilnya lebih fokus. \cmd{apt show} menampilkan detail lengkap: versi, ukuran,
deskripsi, dan dependensi. \cmd{dpkg -l} mendaftar semua paket dengan statusnya,
di mana awalan \texttt{ii} berarti terinstal lengkap dan \texttt{rc} berarti
sudah dihapus tetapi konfigurasi masih ada. \cmd{dpkg -L} mendaftar semua file
yang dimiliki sebuah paket, dan \cmd{dpkg -S} menjawab pertanyaan ``file ini
dipasang oleh paket apa?''

\subsection*{Praktikum 13.1: Instal, Verifikasi, dan Hapus Paket}

Tujuan praktikum ini adalah memahami siklus hidup paket secara menyeluruh,
dari pencarian hingga penghapusan bersih.

\begin{enumerate}
    \item Pastikan daftar paket mutakhir, lalu cari informasi paket \cmd{tree}:
\begin{lstlisting}[language=bash, caption={Perbarui dan cari informasi paket}]
cd ~/lab-os/week13-apps
sudo apt update
apt search --names-only "^tree$"
apt show tree
apt depends tree
\end{lstlisting}
    \textit{Amati:} berapa dependensi yang dimiliki \cmd{tree}? Apakah semua
    sudah terinstal di sistem kamu?

    \item Instal paket \cmd{tree} dan verifikasi hasilnya:
\begin{lstlisting}[language=bash, caption={Instal dan verifikasi paket tree}]
sudo apt install tree -y
dpkg -l tree
dpkg -L tree
which tree
tree --version
tree ~/lab-os/
\end{lstlisting}
    \textit{Amati:} perhatikan kolom status pada output \cmd{dpkg -l}. Apa arti
    awalan \texttt{ii}?

    \item Gunakan \cmd{dpkg -S} untuk menyelidiki beberapa binary sistem:
\begin{lstlisting}[language=bash, caption={Mencari paket pemilik file}]
dpkg -S /bin/ls
dpkg -S /usr/bin/ssh
dpkg -S $(which tree)
\end{lstlisting}

    \item Hapus paket \cmd{tree} dengan purge dan verifikasi tidak ada sisa:
\begin{lstlisting}[language=bash, caption={Hapus paket dan verifikasi sisa}]
sudo apt purge tree -y
sudo apt autoremove -y
dpkg -l tree
apt list --installed 2>/dev/null | grep "^tree"
\end{lstlisting}
    \textit{Amati:} setelah \cmd{purge}, apakah status paket berubah menjadi
    \texttt{rc} atau hilang sepenuhnya?
\end{enumerate}

\begin{challengebox}
Cari semua paket terinstal yang berkaitan dengan Python menggunakan kombinasi
\cmd{apt list --installed} dan \cmd{grep} (dari Bab~2), lalu tampilkan juga
versi masing-masing paket. Simpan hasilnya ke file \file{python-packages.txt}
di direktori lab menggunakan redirection (dari Bab~3). Hitung berapa total
paket Python yang terinstal.
\end{challengebox}

\section{Manajemen Repositori}
\label{sec:repository-management}
%% ========================================================================

Repositori adalah server yang menyimpan koleksi paket beserta metadata-nya.
Bayangkan repositori seperti jaringan toko waralaba: ada toko resmi Ubuntu yang
menjamin kualitas barangnya, dan ada toko pihak ketiga yang menjual produk
spesifik yang belum tersedia di toko resmi. Kamu bisa menambahkan toko pihak
ketiga ke daftar belanjamu, tetapi kamu perlu memverifikasi bahwa toko itu
terpercaya terlebih dahulu.

Konfigurasi repositori disimpan di dua lokasi. File utama adalah
\file{/etc/apt/sources.list}, dan direktori \dir{/etc/apt/sources.list.d/}
berisi file konfigurasi tambahan untuk setiap repositori pihak ketiga. Memisahkan
setiap repositori ke file tersendiri memudahkan pengelolaan karena kamu bisa
menghapus satu repositori cukup dengan menghapus satu file.

Format setiap baris di \file{sources.list} mengikuti pola yang konsisten.

\begin{lstlisting}[language=bash, caption={Format entri sources.list dan contohnya}]
# Format: deb [opsi] URI suite komponen
deb http://archive.ubuntu.com/ubuntu jammy main restricted
deb http://archive.ubuntu.com/ubuntu jammy universe multiverse
deb http://archive.ubuntu.com/ubuntu jammy-security main restricted

# Contoh repositori pihak ketiga dengan signed-by modern
deb [signed-by=/usr/share/keyrings/nginx-archive-keyring.gpg] \
    http://nginx.org/packages/ubuntu jammy nginx
\end{lstlisting}

Kolom \texttt{deb} menunjukkan paket binary. URI adalah alamat server repositori.
\texttt{jammy} adalah kode nama Ubuntu 22.04. Komponen \texttt{main} berisi
software open-source yang didukung resmi, \texttt{restricted} berisi driver
proprietari seperti NVIDIA, \texttt{universe} berisi paket open-source yang
dipelihara komunitas, dan \texttt{multiverse} berisi software yang tidak
sepenuhnya bebas.

Menambahkan repositori pihak ketiga memerlukan dua langkah penting: menyimpan
kunci GPG repositori itu secara lokal, lalu mendaftarkan repositorinya dengan
referensi ke kunci tersebut.

\begin{lstlisting}[language=bash, caption={Menambahkan repositori pihak ketiga dengan metode modern}]
sudo apt install -y curl gnupg2

curl -fsSL https://nginx.org/keys/nginx_signing.key | \
    sudo gpg --dearmor -o /usr/share/keyrings/nginx-archive-keyring.gpg

echo "deb [signed-by=/usr/share/keyrings/nginx-archive-keyring.gpg] \
    http://nginx.org/packages/ubuntu $(lsb_release -cs) nginx" | \
    sudo tee /etc/apt/sources.list.d/nginx.list

sudo apt update
apt-cache policy nginx
\end{lstlisting}

\begin{notebox}
Metode lama menggunakan \cmd{apt-key add} sudah \emph{deprecated} sejak Ubuntu
22.04. Kunci yang ditambahkan dengan cara lama berlaku untuk semua repositori,
bukan hanya satu. Metode \texttt{signed-by} modern membatasi kepercayaan kunci
hanya untuk repositori yang bersangkutan, sehingga lebih aman.
\end{notebox}

Untuk repositori yang berasal dari Launchpad Ubuntu (dikenal sebagai PPA atau
\emph{Personal Package Archive}), ada perintah yang lebih praktis.

\begin{lstlisting}[language=bash, caption={Mengelola PPA dengan add-apt-repository}]
sudo add-apt-repository ppa:git-core/ppa -y
sudo apt update
apt-cache policy git

sudo add-apt-repository --remove ppa:git-core/ppa -y
sudo apt update
\end{lstlisting}

Perintah \cmd{add-apt-repository} mengurus pengunduhan kunci GPG dan pembuatan
file konfigurasi secara otomatis. Opsi \texttt{--remove} membalik proses itu.
Perintah \cmd{apt-cache policy} tanpa argumen nama paket menampilkan semua
sumber aktif beserta prioritasnya.

\subsection*{Praktikum 13.2: Tambahkan Repositori Pihak Ketiga}

Tujuan praktikum ini adalah menambahkan repositori PPA, mengamati perubahan
yang terjadi, lalu membersihkan kembali.

\begin{enumerate}
    \item Periksa konfigurasi repositori yang sedang aktif:
\begin{lstlisting}[language=bash, caption={Memeriksa repositori aktif}]
cat /etc/apt/sources.list
ls -la /etc/apt/sources.list.d/
apt-cache policy | head -20
\end{lstlisting}
    \textit{Amati:} berapa banyak sumber repositori yang terdaftar saat ini?

    \item Tambahkan PPA git-core dan amati perubahannya:
\begin{lstlisting}[language=bash, caption={Menambahkan PPA dan memeriksa hasilnya}]
sudo add-apt-repository ppa:git-core/ppa -y
sudo apt update
apt-cache policy git
ls /etc/apt/sources.list.d/ | grep git
\end{lstlisting}
    \textit{Amati:} pada output \cmd{apt-cache policy git}, ada berapa sumber
    yang menawarkan paket git? Versi mana yang akan diinstal jika kamu
    menjalankan \cmd{apt install git}?

    \item Periksa file konfigurasi yang dibuat oleh \cmd{add-apt-repository}:
\begin{lstlisting}[language=bash, caption={Memeriksa file konfigurasi PPA baru}]
cat /etc/apt/sources.list.d/*git*.list 2>/dev/null || \
    cat /etc/apt/sources.list.d/*git*.sources 2>/dev/null
ls /usr/share/keyrings/ | grep git
\end{lstlisting}

    \item Hapus PPA dan verifikasi kembali:
\begin{lstlisting}[language=bash, caption={Menghapus PPA dan verifikasi}]
sudo add-apt-repository --remove ppa:git-core/ppa -y
sudo apt update
ls /etc/apt/sources.list.d/ | grep git
apt-cache policy git
\end{lstlisting}
    \textit{Amati:} setelah penghapusan, apakah sumber dari Launchpad masih
    muncul di output \cmd{apt-cache policy git}?
\end{enumerate}

Buat skrip Bash (merujuk ke Bab~9) bernama \file{cek-repo.sh} di direktori lab

atau \dir{/etc/apt/sources.list.d/}. Jika sudah ada, skrip mencetak pesan

untuk ditambahkan.
\end{challengebox}

\section{Kompilasi dari Kode Sumber}
\label{sec:compile-from-source}
%% ========================================================================

Ada situasi di mana paket yang kamu butuhkan tidak tersedia di repositori mana
pun: versinya terlalu baru, kamu perlu mengaktifkan fitur tertentu yang tidak
disertakan di build standar, atau kamu sedang mengembangkan program sendiri.
Dalam kasus itu, kompilasi dari kode sumber adalah jalannya.

Analogi yang tepat adalah memasak dari bahan mentah. Package manager seperti
memesan makanan jadi dari restoran, kompilasi dari source seperti memasak sendiri
dari bahan-bahan yang kamu pilih sendiri. Hasilnya bisa dikustomisasi, tetapi
prosesnya lebih panjang.

Langkah pertama adalah memastikan peralatan memasak tersedia. Di Linux, paket
\texttt{build-essential} adalah perangkat lengkap yang menginstal kompiler C
(\cmd{gcc}), kompiler C++ (\cmd{g++}), \cmd{make}, dan header yang dibutuhkan.

\begin{lstlisting}[language=bash, caption={Instalasi build tools}]
sudo apt install build-essential -y
gcc --version
make --version
\end{lstlisting}

Sebagian besar proyek open-source menggunakan pola kompilasi tiga langkah yang
disebut autotools. Langkah pertama adalah \cmd{./configure}, yang memeriksa
lingkungan sistem dan menghasilkan \file{Makefile} yang disesuaikan. Opsi
\texttt{--prefix} menentukan di mana program akan dipasang setelah dikompilasi.
Konvensi standar menggunakan \dir{/usr/local} untuk software yang dipasang di
luar package manager.

\begin{lstlisting}[language=bash, caption={Pola kompilasi autotools}]
./configure --prefix=/usr/local
./configure --help | grep "with\|without\|enable\|disable"

make
make -j$(nproc)

sudo make install
sudo make uninstall
\end{lstlisting}

Langkah kedua adalah \cmd{make}, yang mengompilasi kode menjadi binary. Opsi
\texttt{-j\$(nproc)} menjalankan kompilasi secara paralel menggunakan semua
core CPU yang tersedia, mempercepat proses secara signifikan. \texttt{\$(nproc)}
adalah substitusi perintah yang mengembalikan jumlah core.

Langkah ketiga, \cmd{sudo make install}, menyalin hasil kompilasi ke lokasi
yang ditentukan saat \cmd{./configure}. Beberapa proyek juga menyediakan target
\texttt{uninstall} untuk membersihkan file yang dipasang.

\begin{tipbox}
Pertimbangkan menggunakan \cmd{checkinstall} sebagai pengganti \cmd{make install}.
Alih-alih langsung menyalin file, \cmd{checkinstall} membungkus hasilnya menjadi
paket \texttt{.deb} yang kemudian diinstal melalui \cmd{dpkg}. Hasilnya dapat
dihapus rapi dengan \cmd{apt remove}, berbeda dari file yang tersebar di
\dir{/usr/local/} tanpa catatan apapun.
\end{tipbox}

\subsection*{Praktikum 13.3: Kompilasi Program Sederhana dari Source}

Tujuan praktikum ini adalah memahami setiap langkah kompilasi dari source
dengan mengompilasi program C sederhana menggunakan Makefile buatan sendiri.

\begin{enumerate}
    \item Verifikasi build tools dan buat direktori kerja:
\begin{lstlisting}[language=bash, caption={Persiapan lingkungan kompilasi}]
cd ~/lab-os/week13-apps
sudo apt install build-essential -y
gcc --version
make --version
mkdir -p src-compile
cd src-compile
\end{lstlisting}

    \item Buat program C sederhana:
\begin{lstlisting}[language=bash, caption={Membuat source code program C}]
cat > salam.c << 'EOF'
#include <stdio.h>
#include <stdlib.h>

int main(int argc, char *argv[]) {
    if (argc < 2) {
        printf("Penggunaan: %s <nama>\n", argv[0]);
        return 1;
    }
    printf("Halo, %s! Dikompilasi dari source code.\n", argv[1]);
    return 0;
}
EOF
\end{lstlisting}

    \item Kompilasi secara manual untuk memahami proses dasarnya:
\begin{lstlisting}[language=bash, caption={Kompilasi manual dengan gcc}]
gcc -Wall -O2 -o salam salam.c
ls -lh salam
file salam
./salam Dunia
./salam
\end{lstlisting}
    \textit{Amati:} apa output \cmd{file salam}? Apa arti flag \texttt{-Wall}
    dan \texttt{-O2}?

    \item Buat Makefile untuk mengotomatisasi proses build dan install:
\begin{lstlisting}[language=bash, caption={Membuat Makefile dengan target install dan uninstall}]
cat > Makefile << 'EOF'
PREFIX ?= /usr/local
CC = gcc
CFLAGS = -Wall -O2

all: salam

salam: salam.c
	$(CC) $(CFLAGS) -o salam salam.c

install: salam
	install -D -m 755 salam $(PREFIX)/bin/salam
	@echo "Terpasang ke $(PREFIX)/bin/salam"

uninstall:
	rm -f $(PREFIX)/bin/salam
	@echo "Dihapus dari $(PREFIX)/bin/salam"

clean:
	rm -f salam

.PHONY: all install uninstall clean
EOF
\end{lstlisting}

    \item Jalankan proses build dan install:
\begin{lstlisting}[language=bash, caption={Build dan install dengan Makefile}]
make clean
make
make -n install
sudo make install
which salam
salam Linux
\end{lstlisting}
    \textit{Amati:} \cmd{make -n} adalah dry run yang menampilkan apa yang
    akan dilakukan tanpa menjalankannya. Bandingkan outputnya dengan perintah
    yang benar-benar dijalankan saat \cmd{make install}.

    \item Bersihkan setelah praktikum:
\begin{lstlisting}[language=bash, caption={Uninstall dan bersihkan direktori}]
sudo make uninstall
ls /usr/local/bin/salam 2>/dev/null || echo "File berhasil dihapus"
cd ~/lab-os/week13-apps
rm -rf src-compile
\end{lstlisting}
\end{enumerate}

\begin{challengebox}
Buat Makefile minimal untuk program C sederhana yang punya dua file source:
\file{main.c} dan \file{utils.c}. Makefile harus memiliki target \texttt{all},
\texttt{install}, \texttt{uninstall}, dan \texttt{clean}. Target \texttt{all}
harus mengompilasi kedua file dan menghubungkannya menjadi satu binary.
Gunakan variabel \texttt{PREFIX} dengan nilai default \dir{/usr/local} sehingga
lokasi instalasi bisa diubah dari command line dengan \cmd{make install PREFIX=\$HOME/.local}.
\end{challengebox}

\section{Container Docker}
\label{sec:docker-containers}
%% ========================================================================

Container adalah cara menjalankan aplikasi dalam lingkungan yang terisolasi.
Bayangkan container seperti kabin hotel: setiap tamu mendapat kamar sendiri
dengan pintu yang bisa dikunci, namun semua kabin berbagi fondasi gedung yang
sama. Berbeda dengan Virtual Machine (VM) yang seperti membangun gedung baru
untuk setiap tamu lengkap dengan fondasi tersendiri, container jauh lebih
efisien karena berbagi kernel sistem operasi host.

Beberapa konsep dasar perlu dipahami sebelum mulai menggunakan Docker.
\emph{Image} adalah cetakan beku yang berisi sistem file, aplikasi, dan semua
dependensinya. Image bersifat read-only dan tidak berubah setelah dibuat.
\emph{Container} adalah instance yang berjalan dari sebuah image: seperti
mencetak fotokopi dari master dokumen. Satu image bisa menghasilkan banyak
container yang berjalan sekaligus. \emph{Dockerfile} adalah resep yang
mendefinisikan cara membangun image langkah demi langkah.

Instalasi Docker mengikuti pola repositori pihak ketiga yang sudah dibahas di
seksi sebelumnya.

\begin{lstlisting}[language=bash, caption={Instalasi Docker Engine di Ubuntu}]
sudo apt update
sudo apt install -y ca-certificates curl gnupg

sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
    sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

echo \
  "deb [arch=$(dpkg --print-architecture) \
  signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu \
  $(lsb_release -cs) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io
sudo systemctl enable --now docker
docker --version
\end{lstlisting}

Secara default, Docker daemon hanya bisa diakses oleh root. Menambahkan pengguna
ke grup \texttt{docker} memungkinkan penggunaan Docker tanpa \cmd{sudo}.

\begin{lstlisting}[language=bash, caption={Mengizinkan user menggunakan Docker tanpa sudo}]
sudo usermod -aG docker $USER
newgrp docker
docker run hello-world
\end{lstlisting}

Perintah dasar Docker mengikuti pola yang konsisten. Mengelola image dimulai
dengan mengunduhnya dari registry.

\begin{lstlisting}[language=bash, caption={Mengelola image dan menjalankan container}]
docker pull nginx:alpine
docker images

docker run -d --name web-percobaan -p 8080:80 nginx:alpine
docker ps
docker logs web-percobaan
docker exec -it web-percobaan /bin/sh

docker stop web-percobaan
docker rm web-percobaan
docker rmi nginx:alpine
\end{lstlisting}

Opsi \texttt{-d} menjalankan container di background (detached). Opsi \texttt{-p
8080:80} meneruskan port 8080 di host ke port 80 di dalam container. Opsi
\texttt{--name} memberi nama yang mudah diingat. Perintah \cmd{docker exec -it}
membuka shell interaktif di dalam container yang sedang berjalan.

Untuk membuat image kustom, gunakan Dockerfile. Setiap baris instruksi dalam
Dockerfile menambahkan lapisan baru ke image.

\begin{lstlisting}[language=bash, caption={Contoh Dockerfile dan proses build}]
cat > Dockerfile << 'EOF'
FROM nginx:alpine

RUN echo "Menambahkan halaman kustom..."

COPY index.html /usr/share/nginx/html/index.html

EXPOSE 80

CMD ["nginx", "-g", "daemon off;"]
EOF

echo "<h1>Halo dari container kustom!</h1>" > index.html

docker build -t web-kustom:1.0 .
docker images web-kustom
docker run -d --name test-web -p 8080:80 web-kustom:1.0
curl http://localhost:8080
docker stop test-web && docker rm test-web
\end{lstlisting}

Instruksi \texttt{FROM} menentukan image dasar. \texttt{RUN} menjalankan
perintah selama proses build. \texttt{COPY} menyalin file dari direktori build
ke dalam image. \texttt{EXPOSE} mendokumentasikan port yang digunakan. \texttt{CMD}
menentukan perintah default saat container dijalankan.

\subsection*{Praktikum 13.4: Jalankan Aplikasi di Dalam Container}

Tujuan praktikum ini adalah membangun image Docker untuk aplikasi web statis
dan menjalankannya dengan port mapping.

\begin{enumerate}
    \item Buat direktori kerja dan file HTML untuk aplikasi web statis:
\begin{lstlisting}[language=bash, caption={Menyiapkan file aplikasi web}]
cd ~/lab-os/week13-apps
mkdir -p docker-web
cd docker-web

cat > index.html << 'EOF'
<!DOCTYPE html>
<html lang="id">
<head><meta charset="UTF-8"><title>Aplikasi Lab Week 13</title></head>
<body>
  <h1>Manajemen Aplikasi Linux</h1>
  <p>Container berjalan dengan baik.</p>
  <p>Waktu build: PLACEHOLDER</p>
</body>
</html>
EOF

cat > about.html << 'EOF'
<!DOCTYPE html>
<html lang="id">
<head><meta charset="UTF-8"><title>Tentang</title></head>
<body><h1>Tentang Aplikasi Ini</h1><p>Dibuat untuk praktikum Week 13.</p></body>
</html>
EOF
\end{lstlisting}

    \item Buat Dockerfile:
\begin{lstlisting}[language=bash, caption={Membuat Dockerfile untuk web statis}]
cat > Dockerfile << 'EOF'
FROM nginx:alpine

RUN apk add --no-cache tzdata \
    && cp /usr/share/zoneinfo/Asia/Jakarta /etc/localtime \
    && echo "Asia/Jakarta" > /etc/timezone \
    && apk del tzdata

COPY index.html /usr/share/nginx/html/index.html
COPY about.html /usr/share/nginx/html/about.html

EXPOSE 80

CMD ["nginx", "-g", "daemon off;"]
EOF
\end{lstlisting}

    \item Build image dan jalankan container:
\begin{lstlisting}[language=bash, caption={Build image dan jalankan container}]
docker build -t lab-web13:1.0 .
docker images lab-web13

docker run -d --name lab-web13-container -p 8080:80 lab-web13:1.0
docker ps
\end{lstlisting}
    \textit{Amati:} berapa ukuran image yang dihasilkan dibandingkan image dasar
    \texttt{nginx:alpine}?

    \item Verifikasi aplikasi berjalan dan periksa log:
\begin{lstlisting}[language=bash, caption={Verifikasi aplikasi dan periksa log}]
curl http://localhost:8080
curl http://localhost:8080/about.html
docker logs lab-web13-container
docker exec -it lab-web13-container ls /usr/share/nginx/html/
\end{lstlisting}
    \textit{Amati:} setiap akses halaman via \cmd{curl} menghasilkan entri baru
    di log. Apa format log nginx yang terlihat?

    \item Hentikan container dan bersihkan:
\begin{lstlisting}[language=bash, caption={Bersihkan container dan image}]
docker stop lab-web13-container
docker rm lab-web13-container
docker rmi lab-web13:1.0
cd ~/lab-os/week13-apps
rm -rf docker-web
\end{lstlisting}
\end{enumerate}

\begin{challengebox}
Buat Dockerfile untuk aplikasi web statis yang menggunakan volume untuk
konten HTML. Jalankan container dengan opsi \texttt{-v \$(pwd)/html:/usr/share/nginx/html:ro}
sehingga konten diambil dari direktori host, bukan disalin ke dalam image.
Ubah isi file HTML di direktori host, muat ulang dengan \cmd{curl}, dan amati
bahwa perubahan langsung terlihat tanpa perlu rebuild image. Jelaskan perbedaan
pendekatan ini dibandingkan \texttt{COPY} di Dockerfile untuk lingkungan
pengembangan versus produksi.
\end{challengebox}

\section{Pemantauan Performa Aplikasi}
\label{sec:app-monitoring}
%% ========================================================================

Menginstal aplikasi hanyalah setengah dari pekerjaan. Memastikan aplikasi berjalan
dengan sehat dan menggunakan sumber daya secara wajar adalah pekerjaan berkelanjutan.
Linux menyediakan serangkaian alat untuk melihat apa yang sedang dilakukan sebuah
proses: berapa CPU dan memori yang dikonsumsi, file apa yang dibuka, dan port
jaringan mana yang digunakan.

Perintah \cmd{ps} adalah titik awal yang selalu tersedia. Perintah \cmd{top}
dan \cmd{htop} memberikan tampilan real-time yang terus diperbarui.

\begin{lstlisting}[language=bash, caption={Memantau proses dengan ps dan top}]
ps aux
ps aux | grep nginx
ps aux --sort=-%mem | head -10
ps aux --sort=-%cpu | head -10

top
top -b -n 1 | head -30

htop
\end{lstlisting}

\cmd{ps aux} menampilkan semua proses dengan kolom \texttt{PID}, \texttt{\%CPU},
\texttt{\%MEM}, \texttt{VSZ} (virtual memory), \texttt{RSS} (physical memory
yang benar-benar digunakan), dan \texttt{COMMAND}. Opsi \texttt{--sort=\%-mem}
mengurutkan berdasarkan penggunaan memori tertinggi. Opsi \texttt{-b -n 1} pada
\cmd{top} menghasilkan satu snapshot dalam mode batch, berguna untuk skrip atau
logging.

Untuk mengetahui file apa yang sedang dibuka oleh sebuah proses, gunakan
\cmd{lsof} (\emph{list open files}). Di Linux, segala sesuatu adalah file:
termasuk socket jaringan, pipe, dan perangkat.

\begin{lstlisting}[language=bash, caption={Memantau file terbuka dan koneksi jaringan}]
sudo lsof -p $(pgrep nginx | head -1)
sudo lsof -i :80
sudo lsof -i -nP | grep LISTEN

ss -tlnp
ss -tlnp | grep :80
ss -an | grep ESTABLISHED | wc -l
\end{lstlisting}

\cmd{lsof -p PID} menampilkan semua file yang dibuka proses tertentu. \cmd{lsof
-i :80} menampilkan proses yang menggunakan port 80. Perintah \cmd{ss} adalah
pengganti modern \cmd{netstat}. Opsi \texttt{-t} untuk TCP, \texttt{-l} untuk
yang sedang mendengarkan, \texttt{-n} untuk angka (tidak resolve nama), \texttt{-p}
untuk nama proses. Kombinasi \cmd{ss -tlnp} adalah cara cepat melihat semua
port yang sedang aktif beserta program yang memegangnya.

Untuk kasus diagnosis mendalam, \cmd{strace} memungkinkan kamu melihat setiap
\emph{system call} yang dipanggil sebuah proses. Ini berguna ketika sebuah program
gagal tanpa pesan error yang jelas.

\begin{lstlisting}[language=bash, caption={Analisis mendalam dengan strace dan ldd}]
strace ls /tmp 2>&1 | tail -10
strace -c ls /tmp 2>&1

ldd /usr/bin/ls
ldd /usr/bin/ls | grep "not found"
\end{lstlisting}

\cmd{strace -c} merangkum frekuensi setiap system call tanpa menampilkan detailnya,
berguna untuk profiling cepat. \cmd{ldd} menampilkan semua shared library yang
dibutuhkan sebuah binary. Output \texttt{not found} menunjukkan library yang
hilang, penyebab umum program gagal berjalan meski sudah terinstal.

\begin{warningbox}
\cmd{strace} memperlambat proses target secara signifikan, bisa 10 hingga 100
kali lebih lambat dari normal. Jangan gunakan pada server produksi yang sedang
melayani traffic tinggi. Gunakan opsi \texttt{-e trace=} untuk membatasi hanya
system call yang relevan, misalnya \texttt{-e trace=file} untuk aktivitas file.
\end{warningbox}

\section{Rangkuman}
\label{sec:appmanagement-summary}
%% ========================================================================

Dalam bab ini, kamu telah mempelajari:

\begin{itemize}[noitemsep,topsep=2pt]
    \item \textbf{apt dan dpkg}: dua lapisan manajemen paket Ubuntu, di mana
        \cmd{apt} mengurus dependensi otomatis di atas \cmd{dpkg} yang bekerja
        langsung dengan file \texttt{.deb}.
    \item \textbf{Siklus paket}: alur instalasi (\cmd{apt install}), verifikasi
        (\cmd{dpkg -l}, \cmd{dpkg -L}), pembaruan (\cmd{apt upgrade}), dan
        penghapusan bersih (\cmd{apt purge} diikuti \cmd{autoremove}).
    \item \textbf{Repositori}: konfigurasi di \file{/etc/apt/sources.list} dan
        \dir{sources.list.d/}, serta cara menambahkan repositori pihak ketiga
        menggunakan metode \texttt{signed-by} yang aman.
    \item \textbf{Kompilasi dari source}: pola tiga langkah autotools
        (\cmd{./configure}, \cmd{make}, \cmd{make install}) dan pembuatan
        Makefile untuk mengotomatisasi proses build.
    \item \textbf{Docker}: konsep image dan container, pembuatan image dengan
        Dockerfile, serta menjalankan container dengan port mapping dan volume.
    \item \textbf{Pemantauan aplikasi}: alat \cmd{ps}, \cmd{top}, \cmd{lsof},
        \cmd{ss}, \cmd{ldd}, dan \cmd{strace} untuk memahami perilaku dan
        kesehatan aplikasi yang berjalan.
\end{itemize}

\section{Tugas Praktikum}
\label{sec:appmanagement-exercises}
%% ========================================================================

\textbf{Instruksi Umum}: Kerjakan seluruh tugas secara mandiri. Dokumentasikan
setiap langkah dengan tangkapan layar dan kumpulkan dalam format PDF.

\begin{exercisebox}[13.1 Audit Paket dan Repositori]
Lakukan audit menyeluruh terhadap kondisi paket di sistem Ubuntu kamu.
\begin{enumerate}
    \item Tampilkan jumlah total paket terinstal menggunakan \cmd{dpkg -l | grep
        "\^{}ii" | wc -l}.
    \item Cari semua paket terinstal yang namanya mengandung kata ``lib'' dan
        simpan hasilnya ke file \file{lib-packages.txt} menggunakan redirection.
    \item Identifikasi paket yang berstatus \texttt{rc} (konfigurasi tersisa)
        dengan \cmd{dpkg -l | grep "\^{}rc"}. Jelaskan mengapa paket bisa berada
        dalam status ini.
    \item Periksa apakah ada pembaruan yang tersedia dengan \cmd{apt list
        --upgradable 2>/dev/null}. Catat berapa paket yang bisa diperbarui.
\end{enumerate}
\end{exercisebox}

\begin{exercisebox}[13.2 Kompilasi dan Containerisasi]
Gabungkan dua keterampilan dari bab ini: kompilasi dari source dan Docker.
\begin{enumerate}
    \item Buat program C sederhana yang mencetak informasi sistem: nama host,
        tanggal saat ini, dan pesan selamat datang. Kompilasi menggunakan Makefile.
    \item Buat Dockerfile yang menggunakan \texttt{ubuntu:22.04} sebagai base
        image, menginstal \texttt{build-essential}, menyalin source code ke
        dalam image, mengompilasi di dalam container saat build, dan menjalankan
        binary sebagai \texttt{CMD}.
    \item Build image tersebut dan jalankan container. Verifikasi output program
        muncul di terminal.
    \item Periksa ukuran image yang dihasilkan dengan \cmd{docker images}.
        Jelaskan mengapa image ini jauh lebih besar dari \texttt{nginx:alpine}.
\end{enumerate}
\end{exercisebox}

\begin{exercisebox}[13.3 Diagnosis Masalah Aplikasi]
Sebuah web server dilaporkan tidak bisa distart karena port sudah terpakai.
\begin{enumerate}
    \item Gunakan \cmd{ss -tlnp} untuk mengidentifikasi semua port yang sedang
        aktif di sistem kamu. Catat proses apa yang menggunakan port 80 dan 443
        jika ada.
    \item Jalankan container nginx: \cmd{docker run -d --name test-nginx -p 8080:80
        nginx:alpine}. Kemudian gunakan \cmd{lsof -i :8080} dan \cmd{ss -tlnp |
        grep 8080} untuk membuktikan port 8080 sudah dipakai.
    \item Coba jalankan container nginx kedua dengan port yang sama:
        \cmd{docker run -d --name test-nginx2 -p 8080:80 nginx:alpine}.
        Catat pesan error yang muncul.
    \item Tulis skrip Bash \file{cek-port.sh} yang menerima argumen nomor port,
        memeriksa apakah port tersebut sudah digunakan menggunakan \cmd{ss},
        dan mencetak pesan informatif beserta nama proses yang memakainya.
    \item Bersihkan: \cmd{docker stop test-nginx \&\& docker rm test-nginx}.
\end{enumerate}
\end{exercisebox}
