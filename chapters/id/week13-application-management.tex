\chapter{Manajemen Aplikasi}
\label{ch:application-management}

Bab ini membahas pengelolaan software di lingkungan Linux secara menyeluruh:
sistem manajemen paket (\cmd{apt} dan \cmd{dpkg}), manajemen repositori, kompilasi
dari source code, penggunaan container dengan Docker, serta pemantauan dan
pemecahan masalah aplikasi. Setiap topik disajikan mulai dari teori kemudian
dilanjutkan dengan praktikum di Ubuntu Server 22.04.

%% ========================================================================
\section{Sistem Manajemen Paket}
\label{sec:package-management}
%% ========================================================================

Sistem manajemen paket adalah komponen inti dari setiap distribusi Linux modern.
Alih-alih mengunduh dan menginstal software secara manual, administrator sistem
menggunakan package manager untuk menangani seluruh siklus hidup software:
pencarian, instalasi, pembaruan, penghapusan, dan pelacakan dependensi secara
otomatis.

\subsection{Arsitektur Manajemen Paket di Debian/Ubuntu}

Ubuntu mewarisi sistem manajemen paket dari Debian. Arsitekturnya terdiri dari dua
lapisan:

\begin{description}
    \item[dpkg] Alat tingkat rendah yang bekerja langsung dengan file \file{.deb}.
        Menangani instalasi dan penghapusan fisik paket, tetapi tidak mengelola
        dependensi secara otomatis.
    \item[apt] Alat tingkat tinggi yang bekerja di atas dpkg. Mengunduh paket dari
        repositori, menyelesaikan dependensi secara otomatis, dan menyediakan
        antarmuka yang lebih ramah pengguna.
\end{description}

Dalam praktik sehari-hari, administrator hampir selalu menggunakan \cmd{apt} untuk
tugas rutin. \cmd{dpkg} digunakan saat menginstal file \file{.deb} yang diunduh
manual, atau untuk inspeksi paket yang sudah terinstall.

\subsection{apt: Manajemen Paket Tingkat Tinggi}

\subsubsection{Memperbarui Daftar Paket dan Sistem}

\begin{lstlisting}[language=bash, caption={Memperbarui indeks dan sistem}]
sudo apt update
sudo apt upgrade
sudo apt full-upgrade
sudo apt dist-upgrade
sudo apt update && sudo apt upgrade -y
\end{lstlisting}

Perintah \cmd{apt update} mengunduh daftar paket terbaru dari semua repositori
yang dikonfigurasi; perintah ini harus selalu dijalankan sebelum operasi lain
agar informasi versi paket mutakhir. Perbedaan \texttt{upgrade} dan
\texttt{full-upgrade}: \texttt{upgrade} tidak menghapus paket apapun saat
memperbarui, sedangkan \texttt{full-upgrade} (sinonim \texttt{dist-upgrade})
boleh menghapus paket lama jika diperlukan untuk menyelesaikan konflik dependensi.
Opsi \texttt{-y} menjawab ``ya'' otomatis pada semua konfirmasi, berguna untuk
skrip otomatis.

\subsubsection{Instalasi dan Penghapusan Paket}

\begin{lstlisting}[language=bash, caption={Instalasi dan penghapusan paket}]
sudo apt install nginx
sudo apt install nginx php8.1-fpm mariadb-server
sudo apt install nginx=1.18.0-0ubuntu1.4
sudo apt remove nginx
sudo apt purge nginx
sudo apt autoremove
sudo apt autoremove --purge
\end{lstlisting}

Perintah \cmd{install} menginstal satu atau lebih paket sekaligus beserta semua
dependensinya. Menambahkan \texttt{=versi} setelah nama paket memaksa instalasi
versi tertentu, berguna untuk menjamin kompatibilitas. Perbedaan \texttt{remove}
dan \texttt{purge}: \texttt{remove} menghapus program tetapi menyisakan file
konfigurasi di \dir{/etc/}, sementara \texttt{purge} menghapus program beserta
seluruh file konfigurasinya. Perintah \texttt{autoremove} menghapus paket yang
diinstal sebagai dependensi tetapi sekarang tidak dibutuhkan lagi oleh paket manapun.

\begin{tipbox}
Gunakan \cmd{apt purge} diikuti \cmd{apt autoremove --purge} saat menghapus
layanan seperti MySQL atau PostgreSQL agar tidak ada file konfigurasi atau data
sisa yang dapat menyebabkan konflik saat instalasi ulang.
\end{tipbox}

\subsubsection{Pencarian dan Inspeksi Paket}

\begin{lstlisting}[language=bash, caption={Mencari dan memeriksa informasi paket}]
apt search web server
apt search --names-only nginx
apt show nginx
apt list --installed
apt list --installed | grep nginx
apt list --upgradable
apt depends nginx
apt rdepends nginx
\end{lstlisting}

Perintah \texttt{apt search} mencari paket berdasarkan nama dan deskripsi;
\texttt{--names-only} membatasi pencarian hanya pada nama paket sehingga hasilnya
lebih fokus. Perintah \texttt{apt show} menampilkan informasi lengkap sebuah paket:
versi, ukuran, dependensi, deskripsi, dan homepage. Perintah \texttt{apt list
--installed} mendaftar semua paket yang terinstall. Perintah \texttt{apt depends}
menampilkan daftar dependensi paket, sedangkan \texttt{apt rdepends} (reverse
depends) menampilkan paket-paket yang bergantung pada paket tersebut.

\subsection{dpkg: Manajemen Paket Tingkat Rendah}

\subsubsection{Inspeksi Paket Terinstall}

\begin{lstlisting}[language=bash, caption={Inspeksi paket dengan dpkg}]
dpkg -l
dpkg -l nginx
dpkg -l | grep "^ii"
dpkg -L nginx
dpkg -s nginx
dpkg -S /usr/sbin/nginx
dpkg --get-selections > installed-packages.txt
\end{lstlisting}

Perintah \cmd{dpkg -l} mendaftar semua paket dengan status instalasi; kolom pertama
menunjukkan status: \texttt{ii} artinya terinstall lengkap, \texttt{rc} artinya
dihapus tetapi konfigurasi masih ada. Opsi \texttt{-L} mendaftar semua file yang
dimiliki sebuah paket. Opsi \texttt{-s} menampilkan status dan informasi paket.
Opsi \texttt{-S} (huruf besar) sangat berguna: diberikan sebuah path file, ia
menampilkan paket mana yang menginstal file tersebut. Opsi \texttt{--get-selections}
mengekspor daftar paket terinstall ke format yang dapat digunakan kembali untuk
instalasi ulang massal.

\subsubsection{Instalasi File .deb Lokal}

\begin{lstlisting}[language=bash, caption={Instalasi dan penanganan file .deb}]
sudo dpkg -i package.deb
sudo apt install -f
sudo dpkg -i package.deb && sudo apt install -f
dpkg -I package.deb
dpkg -c package.deb
\end{lstlisting}

Perintah \cmd{dpkg -i} menginstal file \file{.deb} secara langsung. Jika instalasi
gagal karena dependensi yang belum terpenuhi, perintah \cmd{apt install -f}
(fix-broken) akan mengunduh dan menginstal dependensi yang kurang secara otomatis.
Opsi \texttt{-I} (huruf besar) menampilkan metadata dari file \file{.deb} sebelum
diinstal. Opsi \texttt{-c} menampilkan daftar file yang akan diinstal oleh paket tersebut.

%%: Praktikum ---
\subsection*{Praktikum 11.1: Eksplorasi Manajemen Paket}
\textbf{Tujuan:} memahami alur kerja apt dan dpkg untuk instalasi, inspeksi, dan
penghapusan paket secara tepat.

\textbf{Langkah-langkah:}
\begin{enumerate}
    \item Perbarui daftar paket dan periksa paket yang tersedia untuk diupgrade:\
\begin{lstlisting}[language=bash, caption={Update dan cek upgrade}]
sudo apt update
apt list --upgradable 2>/dev/null | head -20
apt list --upgradable 2>/dev/null | wc -l
\end{lstlisting}

    \item Cari dan inspeksi paket \texttt{tree} sebelum menginstalnya:
\begin{lstlisting}[language=bash, caption={Mencari dan memeriksa informasi paket}]
apt search "^tree$"
apt show tree
apt depends tree
\end{lstlisting}

    \item Install paket \texttt{tree} dan verifikasi instalasinya:
\begin{lstlisting}[language=bash, caption={Instalasi dan verifikasi paket}]
sudo apt install tree -y
dpkg -l tree
dpkg -L tree
which tree
tree --version
\end{lstlisting}

    \item Gunakan \cmd{dpkg -S} untuk mencari tahu paket mana yang memiliki
        beberapa binary sistem:
\begin{lstlisting}[language=bash, caption={Mencari pemilik file dengan dpkg}]
dpkg -S /bin/ls
dpkg -S /usr/bin/ssh
dpkg -S /usr/sbin/nginx 2>/dev/null || echo "nginx tidak terinstall"
\end{lstlisting}

    \item Hapus paket \texttt{tree} dengan purge dan verifikasi tidak ada sisa:
\begin{lstlisting}[language=bash, caption={Menghapus paket dengan purge}]
sudo apt purge tree -y
sudo apt autoremove -y
dpkg -l tree
apt list --installed 2>/dev/null | grep tree
\end{lstlisting}
\end{enumerate}

\begin{exercisebox}[11.1]
\begin{enumerate}
    \item Apa perbedaan output \cmd{dpkg -l} saat paket berstatus \texttt{ii}
        dibandingkan \texttt{rc}? Apa yang menyebabkan paket berstatus \texttt{rc}?
    \item Jalankan \cmd{apt depends curl}. Identifikasi dependensi mana yang bersifat
        wajib (\texttt{Depends}) dan mana yang bersifat opsional (\texttt{Recommends}).
        Apa perbedaan keduanya?
    \item Jelaskan skenario di mana Anda perlu menginstal file \file{.deb} secara
        manual menggunakan \cmd{dpkg -i} daripada menggunakan \cmd{apt install}.
\end{enumerate}
\end{exercisebox}

\section{Manajemen Repositori}
\label{sec:repository-management}
%% ========================================================================

Repositori adalah server yang menyimpan koleksi paket beserta metadata-nya. Ubuntu
dikonfigurasi dengan beberapa repositori resmi, tetapi administrator sering perlu
menambahkan repositori pihak ketiga untuk software yang tidak tersedia di repositori
resmi.

\subsection{Struktur Konfigurasi Repositori}

\subsubsection{File sources.list}

\begin{lstlisting}[language=bash, caption={Melihat konfigurasi repositori}]
cat /etc/apt/sources.list
ls /etc/apt/sources.list.d/
cat /etc/apt/sources.list.d/*.list 2>/dev/null | head -20
\end{lstlisting}

File \file{/etc/apt/sources.list} adalah konfigurasi repositori utama. Direktori
\dir{/etc/apt/sources.list.d/} berisi file konfigurasi tambahan; setiap repositori
pihak ketiga biasanya meletakkan konfigurasinya di sini sebagai file \file{.list}
tersendiri agar mudah dikelola.

\subsubsection{Format Baris sources.list}

\begin{lstlisting}[language=bash, caption={Format entri sources.list}]
# Format: deb [options] URI suite components
deb http://archive.ubuntu.com/ubuntu jammy main restricted
deb http://archive.ubuntu.com/ubuntu jammy universe multiverse
deb http://archive.ubuntu.com/ubuntu jammy-security main restricted
deb http://archive.ubuntu.com/ubuntu jammy-updates main restricted
deb [signed-by=/usr/share/keyrings/nginx-archive-keyring.gpg] \
    http://nginx.org/packages/ubuntu jammy nginx
\end{lstlisting}

Setiap baris terdiri dari: tipe paket (\texttt{deb} untuk binary, \texttt{deb-src}
untuk source code), opsi opsional dalam kurung siku, URI repositori, nama suite
(misalnya \texttt{jammy} untuk Ubuntu 22.04), dan satu atau lebih komponen.
Komponen \texttt{main} berisi software open-source yang didukung resmi, \texttt{restricted}
berisi software berproprietary dengan dukungan resmi (seperti driver NVIDIA),
\texttt{universe} berisi paket open-source yang dipelihara komunitas, dan
\texttt{multiverse} berisi software yang tidak sepenuhnya bebas.

\subsubsection{Menambahkan Repositori Pihak Ketiga}

\begin{lstlisting}[language=bash, caption={Menambahkan repositori dengan GPG key}]
sudo apt install -y curl gnupg2

curl -fsSL https://nginx.org/keys/nginx_signing.key | \
    sudo gpg --dearmor -o /usr/share/keyrings/nginx-archive-keyring.gpg

echo "deb [signed-by=/usr/share/keyrings/nginx-archive-keyring.gpg] \
    http://nginx.org/packages/ubuntu $(lsb_release -cs) nginx" | \
    sudo tee /etc/apt/sources.list.d/nginx.list

sudo apt update
apt-cache policy nginx
\end{lstlisting}

Pola modern penambahan repositori pihak ketiga menggunakan tiga langkah: (1) unduh
dan simpan GPG key repositori ke \dir{/usr/share/keyrings/} menggunakan \cmd{gpg
--dearmor}, (2) buat file konfigurasi di \dir{/etc/apt/sources.list.d/} yang
merujuk ke key tersebut dengan opsi \texttt{signed-by}, (3) jalankan \cmd{apt
update} untuk mengunduh metadata paket dari repositori baru. Perintah
\cmd{apt-cache policy} menampilkan versi yang tersedia dari berbagai repositori
beserta prioritasnya.

\begin{notebox}
Metode lama menggunakan \cmd{apt-key add} sudah \emph{deprecated} sejak Ubuntu
22.04 karena alasan keamanan: key yang ditambahkan dengan \cmd{apt-key} berlaku
untuk semua repositori, bukan hanya repositori yang bersangkutan. Metode
\texttt{signed-by} yang baru membatasi kepercayaan ke repositori tertentu saja.
\end{notebox}

\subsubsection{Mengelola dan Menonaktifkan Repositori}

\begin{lstlisting}[language=bash, caption={Mengelola repositori}]
sudo add-apt-repository ppa:ondrej/php
sudo add-apt-repository --remove ppa:ondrej/php
sudo rm /etc/apt/sources.list.d/nginx.list
sudo apt update
apt-cache policy
\end{lstlisting}

Perintah \cmd{add-apt-repository} menyederhanakan penambahan PPA (Personal Package
Archive) dari Launchpad dengan satu perintah. Opsi \texttt{--remove} menghapus PPA
tersebut. Untuk repositori yang ditambahkan secara manual, hapus file
\file{.list} yang bersangkutan dari \dir{/etc/apt/sources.list.d/}. Perintah
\cmd{apt-cache policy} tanpa argumen menampilkan semua sumber paket yang aktif
beserta prioritasnya.

%%: Praktikum ---
\subsection*{Praktikum 11.2: Manajemen Repositori}
\textbf{Tujuan:} memeriksa konfigurasi repositori aktif, menambahkan repositori
pihak ketiga dengan metode GPG key modern, dan memverifikasi paket dari repositori
baru tersedia.

\textbf{Langkah-langkah:}
\begin{enumerate}
    \item Periksa konfigurasi repositori yang sedang aktif:
\begin{lstlisting}[language=bash, caption={Memeriksa konfigurasi repositori}]
cat /etc/apt/sources.list
ls -la /etc/apt/sources.list.d/
apt-cache policy | head -30
\end{lstlisting}

    \item Periksa berapa banyak paket yang tersedia dari masing-masing sumber:
\begin{lstlisting}[language=bash, caption={Statistik repositori}]
apt-cache stats
apt-cache pkgnames | wc -l
\end{lstlisting}

    \item Tambahkan repositori Git terbaru dari PPA:
\begin{lstlisting}[language=bash, caption={Menambahkan PPA git-core}]
sudo add-apt-repository ppa:git-core/ppa -y
sudo apt update
apt-cache policy git
\end{lstlisting}

    Perhatikan output \cmd{apt-cache policy git}: sekarang ada dua sumber
    (\texttt{archive.ubuntu.com} dan \texttt{ppa.launchpad.net}) dengan versi
    yang mungkin berbeda.

    \item Periksa file konfigurasi yang dibuat oleh \cmd{add-apt-repository}:
\begin{lstlisting}[language=bash, caption={Memeriksa file konfigurasi PPA}]
ls /etc/apt/sources.list.d/ | grep git
cat /etc/apt/sources.list.d/*git*.list 2>/dev/null || \
    cat /etc/apt/sources.list.d/*git*.sources 2>/dev/null
ls /usr/share/keyrings/ | grep git
\end{lstlisting}

    \item Hapus PPA yang baru ditambahkan dan verifikasi:
\begin{lstlisting}[language=bash, caption={Menghapus PPA}]
sudo add-apt-repository --remove ppa:git-core/ppa -y
sudo apt update
ls /etc/apt/sources.list.d/ | grep git
apt-cache policy git
\end{lstlisting}
\end{enumerate}

\begin{exercisebox}[11.2]
\begin{enumerate}
    \item Dari output \cmd{apt-cache policy git} setelah menambahkan PPA, jelaskan
        bagaimana apt menentukan versi mana yang akan diinstall jika Anda menjalankan
        \cmd{apt install git}. Apa artinya angka \texttt{500} dan \texttt{100} di
        kolom prioritas?
    \item Apa risiko keamanan dari menambahkan repositori pihak ketiga yang tidak
        terpercaya? Jelaskan mengapa metode \texttt{signed-by} lebih aman dari
        \cmd{apt-key add} yang lama.
    \item Apa perbedaan antara PPA di Launchpad dan repositori pihak ketiga yang
        dikelola vendor (seperti repositori resmi nginx atau Docker)?
\end{enumerate}
\end{exercisebox}

\section{Kompilasi dari Source Code}
\label{sec:compile-from-source}
%% ========================================================================

Meskipun package manager tersedia untuk sebagian besar software, ada situasi di
mana kompilasi dari source code diperlukan: software terlalu baru untuk masuk ke
repositori, perlu dibangun dengan opsi kustom, atau tidak tersedia sebagai paket
binary untuk arsitektur yang digunakan.

\subsection{Prasyarat: Build Tools}

\begin{lstlisting}[language=bash, caption={Instalasi build tools}]
sudo apt install build-essential
sudo apt install build-essential cmake git
gcc --version
make --version
\end{lstlisting}

Paket \texttt{build-essential} adalah metapaket yang menginstal semua alat yang
dibutuhkan untuk kompilasi: \cmd{gcc} (kompiler C), \cmd{g++} (kompiler C++),
\cmd{make}, \cmd{libc6-dev}, dan header kernel. Ini adalah langkah pertama yang
selalu dilakukan di server Ubuntu baru yang akan digunakan untuk kompilasi.
Perintah \cmd{cmake} adalah sistem build generator modern yang digunakan oleh banyak
proyek C/C++ terkini sebagai pengganti \texttt{autotools}.

\subsection{Pola Kompilasi dengan Autotools}

Banyak proyek open-source lama menggunakan sistem \texttt{autotools} yang mengikuti
pola tiga langkah:

\subsubsection{Langkah-langkah Kompilasi Autotools}

\begin{lstlisting}[language=bash, caption={Pola kompilasi autotools}]
tar -xzf software-1.0.tar.gz
cd software-1.0/

./configure
./configure --prefix=/usr/local --with-openssl --without-debug

make
make -j$(nproc)

sudo make install
\end{lstlisting}

Skrip \cmd{./configure} memeriksa sistem: kompiler tersedia, library yang
dibutuhkan terinstall, dan menghasilkan \file{Makefile} yang disesuaikan untuk
sistem saat ini. Opsi \texttt{--prefix} menentukan direktori instalasi;
\texttt{/usr/local} adalah konvensi untuk software yang diinstall di luar package
manager. Opsi \texttt{--with-*} dan \texttt{--without-*} mengaktifkan atau
menonaktifkan fitur opsional. Perintah \cmd{make} mengompilasi kode; opsi
\texttt{-j\$(nproc)} menjalankan kompilasi paralel menggunakan semua core CPU
tersedia, mempercepat proses secara signifikan pada mesin multicore. Perintah
\cmd{sudo make install} menyalin binary dan file terkait ke lokasi yang
ditentukan saat \texttt{configure}.

\begin{lstlisting}[language=bash, caption={Melihat opsi konfigurasi yang tersedia}]
./configure --help
./configure --help | grep "enable\|disable\|with\|without"
\end{lstlisting}

Menjalankan \cmd{./configure --help} sebelum konfigurasi sebenarnya adalah
praktik yang baik untuk memahami semua opsi yang tersedia, termasuk fitur opsional
dan lokasi library yang mungkin perlu ditentukan secara eksplisit.

\subsubsection{Mengelola Instalasi dari Source}

\begin{lstlisting}[language=bash, caption={Mengelola software yang dikompilasi dari source}]
make -n install
sudo make uninstall

sudo checkinstall
dpkg -l | grep checkinstall
\end{lstlisting}

Opsi \texttt{-n} pada \cmd{make} adalah dry run: menampilkan apa yang akan
dilakukan tanpa benar-benar menjalankannya. Banyak proyek menyediakan target
\texttt{uninstall}, tetapi tidak semua. Alat \cmd{checkinstall} adalah solusi yang
lebih baik: alih-alih langsung menginstal, ia membungkus hasil \cmd{make install}
menjadi paket \file{.deb} yang kemudian diinstall melalui dpkg, sehingga
penghapusan dapat dilakukan dengan \cmd{apt remove} seperti paket biasa.

\begin{tipbox}
Pertimbangkan menggunakan \cmd{checkinstall} daripada \cmd{make install} langsung.
Paket yang dikelola dpkg/apt jauh lebih mudah dihapus dan dilacak dibandingkan
file yang tersebar di \dir{/usr/local/} tanpa registry apapun.
\end{tipbox}

\subsection{Kompilasi dengan CMake}

\begin{lstlisting}[language=bash, caption={Pola kompilasi CMake}]
git clone https://github.com/contoh/project.git
cd project/

mkdir build && cd build
cmake .. -DCMAKE_INSTALL_PREFIX=/usr/local -DCMAKE_BUILD_TYPE=Release
cmake .. -DENABLE_TESTS=ON -DWITH_SSL=ON

make -j$(nproc)
sudo make install
\end{lstlisting}

CMake menggunakan direktori build terpisah (\emph{out-of-source build}) yang menjaga
direktori source tetap bersih: semua file hasil kompilasi berada di
\dir{build/}. Perintah \cmd{cmake ..} memproses \file{CMakeLists.txt} dari
direktori induk. Opsi \texttt{-D} mengatur variabel CMake; \texttt{CMAKE\_BUILD\_TYPE=Release}
mengaktifkan optimasi kompiler sementara \texttt{Debug} menyertakan informasi
debugging.

%%: Praktikum ---
\subsection*{Praktikum 11.3: Kompilasi dari Source Code}
\textbf{Tujuan:} mengompilasi program sederhana dari source code menggunakan
pola autotools, memahami setiap tahap, dan mengelola hasilnya dengan checkinstall.

\textbf{Langkah-langkah:}
\begin{enumerate}
    \item Pastikan build tools terinstall:
\begin{lstlisting}[language=bash, caption={Verifikasi build tools}]
sudo apt install build-essential -y
gcc --version
make --version
which gcc make
\end{lstlisting}

    \item Buat program C sederhana dan kompilasi secara manual untuk memahami
        proses dasar:
\begin{lstlisting}[language=bash, caption={Kompilasi manual program C}]
mkdir -p ~/lab-compile && cd ~/lab-compile

cat > hello.c << 'EOF'
#include <stdio.h>
int main() {
    printf("Hello dari source code!\n");
    return 0;
}
EOF

gcc -o hello hello.c
./hello

gcc -Wall -O2 -o hello-optimized hello.c
ls -lh hello hello-optimized
\end{lstlisting}

    \item Simulasikan pola autotools dengan Makefile manual:
\begin{lstlisting}[language=bash, caption={Membuat dan menggunakan Makefile}]
cat > Makefile << 'EOF'
PREFIX ?= /usr/local

all: hello

hello: hello.c
	gcc -Wall -O2 -o hello hello.c

install: hello
	install -D -m 755 hello $(PREFIX)/bin/hello

uninstall:
	rm -f $(PREFIX)/bin/hello

\section{Container dengan Docker}
\label{sec:docker-containers}
%% ========================================================================

Container adalah teknologi virtualisasi tingkat OS yang mengisolasi aplikasi beserta
seluruh dependensinya ke dalam unit yang portabel dan reproducible. Berbeda dengan
Virtual Machine (VM) yang memvirtualisasi seluruh hardware, container berbagi kernel
dengan host OS sehingga jauh lebih ringan.

\subsection{Konsep Dasar Container}

\begin{description}
    \item[Image] Template read-only yang berisi sistem file, aplikasi, dan
        dependensinya. Image bersifat immutable; setelah dibuat tidak berubah.
    \item[Container] Instance yang sedang berjalan dari sebuah image. Container
        memiliki lapisan read-write di atas image yang menampung perubahan saat
        runtime.
    \item[Registry] Repositori penyimpanan image. Docker Hub adalah registry publik
        terbesar, tetapi organisasi biasanya memiliki private registry sendiri.
    \item[Dockerfile] File instruksi untuk membangun image secara deklaratif.
\end{description}

\cref{fig:docker-vs-vm} mengilustrasikan perbedaan arsitektur mendasar antara
Docker Container dan Virtual Machine. Pada sisi kiri, Docker Engine berjalan
langsung di atas kernel host. Ketiga container (A, B, C) berbagi kernel yang
sama dan hanya membawa library serta aplikasi masing-masing, itulah mengapa
ukuran image Docker jauh lebih kecil dibanding VM. Panah dari Docker Engine
membentuk \emph{T-junction bus}, menunjukkan bahwa engine mengorkestrasi semua
container secara terpusat.

Pada sisi kanan, Hypervisor (misalnya VMware, KVM, atau VirtualBox) berjalan
di atas kernel host dan menyediakan lapisan virtualisasi. Setiap VM harus
membawa \emph{Guest OS Kernel}-nya sendiri, sehingga konsumsi RAM dan disk
jauh lebih besar. Namun isolasi VM lebih kuat karena setiap VM beroperasi
seolah-olah pada hardware tersendiri, celah keamanan di satu VM tidak
langsung memengaruhi VM lain.

\subsection{Instalasi Docker di Ubuntu}

\begin{lstlisting}[language=bash, caption={Instalasi Docker Engine di Ubuntu 22.04}]
sudo apt update
sudo apt install -y ca-certificates curl gnupg

sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
    sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

echo \
  "deb [arch=$(dpkg --print-architecture) \
  signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu \
  $(lsb_release -cs) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io

sudo systemctl enable --now docker
docker --version
\end{lstlisting}

Instalasi Docker resmi menggunakan repositori Docker, bukan paket \texttt{docker.io}
dari repositori Ubuntu (yang versinya sering jauh tertinggal). Proses instalasi
mengikuti pola standar repositori pihak ketiga yang telah dibahas sebelumnya.
Setelah \cmd{systemctl enable --now}, Docker akan aktif sekaligus dikonfigurasi
untuk start otomatis saat boot.

\begin{lstlisting}[language=bash, caption={Menambahkan user ke grup docker}]
sudo usermod -aG docker $USER
newgrp docker
docker run hello-world
\end{lstlisting}

Secara default Docker daemon hanya bisa diakses oleh root. Perintah \cmd{usermod
-aG docker} menambahkan user saat ini ke grup \texttt{docker}, memungkinkan
penggunaan Docker tanpa \cmd{sudo}. Perintah \cmd{newgrp docker} mengaktifkan
keanggotaan grup baru untuk sesi terminal saat ini tanpa perlu logout.

\subsection{Perintah Docker Dasar}

\subsubsection{Mengelola Image}

\begin{lstlisting}[language=bash, caption={Mengelola image Docker}]
docker pull ubuntu:22.04
docker pull nginx:latest
docker pull nginx:1.25-alpine
docker images
docker image ls
docker rmi nginx:latest
docker image prune
\end{lstlisting}

Perintah \cmd{docker pull} mengunduh image dari registry (default: Docker Hub).
Tag setelah tanda titik dua (\texttt{:}) menentukan versi; \texttt{latest} adalah
tag default jika tidak disebutkan. Tag \texttt{alpine} menunjuk ke varian berbasis
Alpine Linux yang jauh lebih kecil (\textasciitilde 5--10 MB vs \textasciitilde
50--200 MB untuk varian standar). Perintah \cmd{docker images} atau \cmd{docker image
ls} mendaftar semua image yang tersimpan lokal. Perintah \cmd{docker rmi} menghapus
image. Perintah \cmd{docker image prune} menghapus semua image yang tidak digunakan.

\subsubsection{Menjalankan dan Mengelola Container}

\begin{lstlisting}[language=bash, caption={Menjalankan dan mengelola container}]
docker run ubuntu:22.04 echo "Hello dari container"
docker run -it ubuntu:22.04 /bin/bash
docker run -d --name web-server -p 8080:80 nginx
docker run -d --name web-server -p 8080:80 -v /var/www:/usr/share/nginx/html nginx
docker ps
docker ps -a
docker stop web-server
docker start web-server
docker rm web-server
docker logs web-server
docker logs -f web-server
docker exec -it web-server /bin/bash
\end{lstlisting}

Opsi \texttt{-it} menggabungkan \texttt{-i} (stdin tetap terhubung) dan \texttt{-t}
(alokasikan pseudo-TTY) untuk sesi interaktif. Opsi \texttt{-d} (detached) menjalankan
container di background. Opsi \texttt{--name} memberi nama yang mudah diingat.
Opsi \texttt{-p host:container} meneruskan port host ke port di dalam container.
Opsi \texttt{-v host-path:container-path} me-mount direktori host ke container,
memungkinkan data persisten melewati siklus hidup container. Perintah \cmd{docker
ps} menampilkan container yang sedang berjalan; \texttt{-a} menampilkan semua
termasuk yang berhenti. Perintah \cmd{docker logs -f} memantau log secara real-time.
Perintah \cmd{docker exec -it} membuka shell di dalam container yang sedang berjalan.

\subsubsection{Membuat Image dengan Dockerfile}

\begin{lstlisting}[language=bash, caption={Contoh Dockerfile aplikasi web sederhana}]
cat > Dockerfile << 'EOF'
FROM ubuntu:22.04

ENV DEBIAN_FRONTEND=noninteractive

RUN apt-get update && apt-get install -y \
    nginx \
    && rm -rf /var/lib/apt/lists/*

COPY index.html /usr/share/nginx/html/

EXPOSE 80

CMD ["nginx", "-g", "daemon off;"]
EOF

echo "<h1>Hello dari Docker!</h1>" > index.html
docker build -t my-webapp:1.0 .
docker images my-webapp
docker run -d -p 8080:80 my-webapp:1.0
curl http://localhost:8080
\end{lstlisting}

Instruksi \texttt{FROM} menentukan image dasar. Instruksi \texttt{RUN} menjalankan
perintah saat membangun image; penghapusan \dir{/var/lib/apt/lists/} mengurangi
ukuran image. Instruksi \texttt{COPY} menyalin file dari konteks build ke dalam
image. Instruksi \texttt{EXPOSE} mendokumentasikan port yang didengarkan container
(tidak secara otomatis mem-publish port). Instruksi \texttt{CMD} menentukan perintah
default yang dijalankan saat container dimulai.

\subsection{Orkestrasi Multi-Container dengan Docker Compose}

Aplikasi nyata jarang berdiri sendiri. Sebuah web application biasanya terdiri dari
beberapa layanan yang berjalan bersamaan: web server, aplikasi backend, database,
dan cache. Mengelola masing-masing container secara terpisah dengan perintah
\cmd{docker run} yang panjang menjadi tidak praktis. Docker Compose menyelesaikan
masalah ini dengan mendefinisikan seluruh stack multi-container dalam satu file
deklaratif \file{docker-compose.yml}.

\subsubsection{Instalasi Docker Compose}

\begin{lstlisting}[language=bash, caption={Instalasi Docker Compose Plugin}]
sudo apt install -y docker-compose-plugin
docker compose version

docker-compose --version
\end{lstlisting}

Docker Compose V2 hadir sebagai plugin Docker (dipanggil dengan \cmd{docker compose}
dua kata) dan sudah termasuk dalam instalasi Docker Engine modern. Versi lama
\cmd{docker-compose} (satu kata, dengan tanda hubung) adalah binary Python yang sudah
\emph{deprecated}. Gunakan \cmd{docker compose} (plugin) untuk instalasi baru.

\subsubsection{Struktur File docker-compose.yml}

\begin{lstlisting}[caption={Contoh docker-compose.yml stack web + database}]
version: "3.9"

services:
  web:
    image: nginx:alpine
    ports:
      - "8080:80"
    volumes:
      - ./html:/usr/share/nginx/html:ro
    depends_on:
      - app
    restart: unless-stopped

  app:
    build: ./app
    environment:
      - DB_HOST=db
      - DB_PORT=5432
      - DB_NAME=mydb
    depends_on:
      - db
    restart: unless-stopped

  db:
    image: postgres:15-alpine
    environment:
      POSTGRES_DB: mydb
      POSTGRES_USER: appuser
      POSTGRES_PASSWORD: secret
    volumes:
      - db-data:/var/lib/postgresql/data
    restart: unless-stopped

volumes:
  db-data:
\end{lstlisting}

File \file{docker-compose.yml} mendefinisikan beberapa bagian utama. Bagian
\texttt{services} berisi daftar container; setiap service memiliki nama yang
sekaligus berfungsi sebagai hostname internal antar container (misalnya service
\texttt{db} dapat dicapai dari container \texttt{app} melalui hostname
\texttt{db}). Kunci \texttt{image} menggunakan image yang sudah ada dari registry,
sedangkan kunci \texttt{build} menunjuk ke direktori yang berisi \texttt{Dockerfile}
untuk dibangun terlebih dahulu. Kunci \texttt{ports} meneruskan port host ke container,
\texttt{volumes} me-mount direktori atau named volume, \texttt{environment} mengatur
variabel lingkungan, dan \texttt{depends\_on} menyatakan urutan start antar service.
Kunci \texttt{restart: unless-stopped} memastikan container restart otomatis setelah
crash atau reboot kecuali dihentikan secara eksplisit.

Bagian \texttt{volumes} di level teratas mendefinisikan \emph{named volumes}: volume
yang dikelola Docker dan persisten melewati siklus hidup container, berbeda dengan
bind mount (direktori host yang di-mount ke container).

\subsubsection{Perintah Docker Compose}

\begin{lstlisting}[language=bash, caption={Perintah dasar Docker Compose}]
docker compose up
docker compose up -d
docker compose up -d --build
docker compose down
docker compose down -v
docker compose ps
docker compose logs
docker compose logs -f web
docker compose exec app /bin/sh
docker compose stop
docker compose start
docker compose restart web
docker compose build
docker compose pull
\end{lstlisting}

Perintah \cmd{docker compose up} membaca \file{docker-compose.yml} di direktori
saat ini lalu membuat dan menjalankan semua service yang didefinisikan. Opsi
\texttt{-d} menjalankan di background. Opsi \texttt{--build} memaksa rebuild image
sebelum start, berguna setelah mengubah Dockerfile. Perintah \cmd{docker compose
down} menghentikan dan menghapus semua container dan jaringan yang dibuat; opsi
\texttt{-v} juga menghapus named volumes (hati-hati: data akan hilang). Perintah
\cmd{docker compose ps} menampilkan status semua service. Perintah \cmd{docker
compose exec service command} menjalankan perintah di dalam container service yang
sedang berjalan, setara dengan \cmd{docker exec} untuk satu container.

\subsubsection{Perbandingan Dockerfile dan Docker Compose}

\begin{table}[htbp]
    \centering
    \caption{Perbandingan Dockerfile dan Docker Compose}
    \label{tab:dockerfile-vs-compose}
    \begin{tblr}{
        colspec = {lX[l]X[l]},
        width = \linewidth,
        hlines,
        vlines,
        row{1} = {font=\bfseries},
        cells = {font=\small}
    }
    \textbf{Aspek} & \textbf{Dockerfile} & \textbf{docker-compose.yml} \\
    Tujuan utama
        & Mendefinisikan \emph{bagaimana} sebuah image dibangun
        & Mendefinisikan \emph{bagaimana} beberapa container dijalankan bersama \\
    Scope
        & Satu image / satu container
        & Satu stack (banyak service/container) \\
    Isi file
        & Instruksi build: FROM, RUN, COPY, CMD, dll.
        & Konfigurasi runtime: port, volume, env var, dependensi antar service \\
    Jaringan
        & Tidak diatur (diserahkan ke docker run)
        & Membuat jaringan internal otomatis; antar service saling bisa dicapai via nama service \\
    Perintah utama
        & docker build
        & docker compose up / down \\
    Hubungan
        & Bisa dirujuk dari Compose via kunci build:
        & Bisa menggunakan image hasil Dockerfile \\
    Kasus penggunaan
        & Membangun image kustom untuk aplikasi
        & Menjalankan lingkungan development, staging, atau produksi lengkap \\
    \end{tblr}
\end{table}

\begin{notebox}
Dockerfile dan Docker Compose bukan alternatif satu sama lain, melainkan
\emph{saling melengkapi}. Dalam proyek nyata keduanya digunakan bersama: Dockerfile
mendefinisikan image aplikasi, sedangkan Docker Compose mendefinisikan bagaimana
image tersebut dijalankan bersama dengan service lain (database, cache, message
broker, dll.).
\end{notebox}

\subsection*{Praktikum 11.4: Pengenalan Docker dan Docker Compose}
\textbf{Tujuan:} menjalankan container dari image yang ada, membuat image kustom
dengan Dockerfile, dan mengelola stack multi-container menggunakan Docker Compose.

\textbf{Langkah-langkah:}
\begin{enumerate}
    \item Verifikasi instalasi Docker dan Docker Compose:
\begin{lstlisting}[language=bash, caption={Verifikasi instalasi Docker}]
docker --version
docker compose version
docker run hello-world
\end{lstlisting}

    \item Eksplorasi container interaktif dan periksa siklus hidupnya:
\begin{lstlisting}[language=bash, caption={Menjalankan container interaktif}]
docker run -it --name lab-ubuntu ubuntu:22.04 /bin/bash
\end{lstlisting}

    Di dalam container, jalankan perintah berikut lalu ketik \cmd{exit}:
\begin{lstlisting}[language=bash, caption={Perintah di dalam container}]
cat /etc/os-release
hostname
ps aux
ip addr show
exit
\end{lstlisting}

\begin{lstlisting}[language=bash, caption={Memeriksa dan menghapus container}]
docker ps -a
docker rm lab-ubuntu
\end{lstlisting}

    \item Buat Dockerfile kustom, build, dan jalankan:
\begin{lstlisting}[language=bash, caption={Membuat image kustom dengan Dockerfile}]
mkdir ~/lab-docker && cd ~/lab-docker

cat > index.html << 'EOF'
<html><body><h1>Web Server Kustom dari Docker</h1></body></html>
EOF

cat > Dockerfile << 'EOF'
FROM nginx:alpine
COPY index.html /usr/share/nginx/html/index.html
EOF

docker build -t lab-web:1.0 .
docker run -d --name lab-web -p 8080:80 lab-web:1.0
curl http://localhost:8080
docker stop lab-web && docker rm lab-web
\end{lstlisting}

    \item Buat stack multi-container dengan Docker Compose (nginx + Redis):
\begin{lstlisting}[language=bash, caption={Membuat docker-compose.yml}]
cat > docker-compose.yml << 'EOF'
version: "3.9"

services:
  web:
    image: nginx:alpine
    ports:
      - "8080:80"
    volumes:
      - ./html:/usr/share/nginx/html:ro
    depends_on:
      - cache
    restart: unless-stopped

  cache:
    image: redis:7-alpine
    restart: unless-stopped

volumes: {}
EOF

mkdir html
echo "<h1>Stack Docker Compose</h1>" > html/index.html
\end{lstlisting}

    \item Jalankan stack dan periksa statusnya:
\begin{lstlisting}[language=bash, caption={Menjalankan dan memantau stack Compose}]
docker compose up -d
docker compose ps
docker compose logs web
curl http://localhost:8080
docker compose exec web wget -qO- http://cache:6379 2>/dev/null || \
    echo "Redis berjalan (tidak menerima HTTP, normal)"
\end{lstlisting}

    \item Hentikan dan bersihkan seluruh stack:
\begin{lstlisting}[language=bash, caption={Membersihkan setelah praktikum}]
docker compose down
docker compose ps
docker rmi lab-web:1.0
cd ~ && rm -rf ~/lab-docker
\end{lstlisting}
\end{enumerate}

\section{Pemantauan dan Pemecahan Masalah Aplikasi}
\label{sec:app-monitoring}
%% ========================================================================

Memantau performa aplikasi dan mendiagnosis masalah adalah keterampilan kritis
administrator sistem. Linux menyediakan berbagai alat untuk memahami apa yang
sedang dilakukan oleh sebuah proses: penggunaan CPU/memori, file yang dibuka,
port jaringan yang digunakan, system call yang dipanggil, dan dependensi library.

\subsection{Pemantauan Proses}

\subsubsection{Informasi Proses Dasar}

\begin{lstlisting}[language=bash, caption={Memantau proses aplikasi}]
ps aux
ps aux | grep nginx
ps aux --sort=-%mem | head -10
ps aux --sort=-%cpu | head -10
ps -eo pid,ppid,cmd,%mem,%cpu --sort=-%mem | head -15
pgrep -a nginx
pidof nginx
\end{lstlisting}

Perintah \cmd{ps aux} menampilkan semua proses dengan informasi lengkap: \texttt{USER}
(pemilik), \texttt{PID} (process ID), \texttt{\%CPU}, \texttt{\%MEM}, \texttt{VSZ}
(virtual memory), \texttt{RSS} (physical memory), dan \texttt{COMMAND}. Opsi
\texttt{--sort=\%-mem} mengurutkan berdasarkan penggunaan memori tertinggi, berguna
untuk menemukan proses yang mengonsumsi memori berlebihan. Opsi \texttt{-eo} memilih
kolom yang ingin ditampilkan. Perintah \cmd{pgrep} mencari PID berdasarkan nama
proses; \cmd{pidof} mencari PID berdasarkan nama binary.

\subsubsection{Pemantauan Real-time}

\begin{lstlisting}[language=bash, caption={Pemantauan real-time dengan top dan htop}]
top
top -p $(pgrep -d, nginx)
top -b -n 1 | head -20
htop
htop -p $(pgrep -d, nginx)
\end{lstlisting}

Perintah \cmd{top} adalah monitor sistem klasik yang diperbarui setiap beberapa
detik. Tekan \texttt{M} untuk mengurutkan berdasarkan memori, \texttt{P} berdasarkan
CPU, \texttt{q} untuk keluar. Opsi \texttt{-p} membatasi tampilan ke PID tertentu.
Opsi \texttt{-b -n 1} menjalankan top sekali dalam mode batch tanpa interaktif,
berguna untuk skrip. Perintah \cmd{htop} adalah versi modern yang lebih interaktif
dengan tampilan berwarna, scroll horizontal, dan tree view proses.

\subsection{Pemantauan File dan Port}

\subsubsection{lsof: Melihat File yang Terbuka}

\begin{lstlisting}[language=bash, caption={Menggunakan lsof}]
sudo lsof -p 1234
sudo lsof -u www-data
sudo lsof /var/log/nginx/access.log
sudo lsof -i :80
sudo lsof -i :80 -i :443
sudo lsof -i tcp
sudo lsof -i -nP | grep LISTEN
\end{lstlisting}

\cmd{lsof} (\textit{list open files}) menampilkan semua file yang sedang dibuka oleh
proses. Di Linux, segala sesuatu adalah file: file reguler, direktori, socket jaringan,
pipe, dan perangkat. Opsi \texttt{-p PID} menampilkan semua file yang dibuka proses
tertentu. Opsi \texttt{-u user} menampilkan file yang dibuka oleh user tertentu.
Memberikan nama file sebagai argumen menampilkan proses mana yang membuka file
tersebut, berguna untuk mengetahui mengapa sebuah file tidak bisa dihapus (masih
digunakan). Opsi \texttt{-i :port} menampilkan proses yang menggunakan port tertentu.
Opsi \texttt{-nP} menonaktifkan resolusi nama host dan nama port untuk output lebih
cepat; filter \texttt{LISTEN} menampilkan hanya port yang sedang mendengarkan.

\subsubsection{ss: Status Socket Jaringan}

\begin{lstlisting}[language=bash, caption={Memeriksa koneksi jaringan dengan ss}]
ss -tlnp
ss -tlnp | grep :80
ss -an | grep ESTABLISHED | wc -l
ss -s
\end{lstlisting}

Perintah \cmd{ss} (\textit{socket statistics}) adalah pengganti modern untuk
\cmd{netstat}. Opsi \texttt{-t} untuk TCP, \texttt{-l} untuk port yang mendengarkan,
\texttt{-n} untuk menampilkan angka (tidak resolve nama), \texttt{-p} untuk
menampilkan nama proses. Perintah \cmd{ss -tlnp} adalah cara cepat untuk melihat
semua port TCP yang sedang didengarkan beserta program yang menggunakannya.
Perintah \cmd{ss -s} menampilkan ringkasan statistik semua socket.

\subsection{Manajemen Dependensi Library}

\begin{lstlisting}[language=bash, caption={Memeriksa dependensi library}]
ldd /usr/sbin/nginx
ldd /usr/sbin/nginx | grep "not found"
ldconfig -p | grep libssl
sudo ldconfig
apt-cache depends nginx
apt-cache rdepends --installed libssl3
\end{lstlisting}

Perintah \cmd{ldd} menampilkan semua shared library yang dibutuhkan sebuah binary.
Output \texttt{not found} menunjukkan library yang hilang: ini adalah penyebab
umum program gagal dijalankan meski sudah terinstal. Perintah \cmd{ldconfig -p}
mendaftar semua library yang dikenal sistem dari cache \cmd{ldconfig}. Perintah
\cmd{ldconfig} (tanpa argumen, dengan sudo) memperbarui cache library setelah
library baru diinstall ke lokasi non-standar. Perintah \cmd{apt-cache rdepends}
menampilkan semua paket terinstall yang bergantung pada library tertentu, berguna
sebelum menghapus atau mengupgrade library.

\subsection{Analisis Mendalam dengan strace}

\begin{lstlisting}[language=bash, caption={Debugging dengan strace}]
strace ls /tmp 2>&1 | tail -20
strace -p 1234
strace -p 1234 -e trace=network
strace -c ls /tmp 2>&1
\end{lstlisting}

\cmd{strace} menampilkan semua system call yang dipanggil oleh sebuah proses.
Ini sangat berguna untuk mendiagnosis masalah yang tidak jelas: misalnya program
gagal membaca file konfigurasi (strace akan menunjukkan path mana yang dicoba),
atau program mencoba koneksi jaringan ke alamat yang salah. Opsi \texttt{-p PID}
melampirkan strace ke proses yang sedang berjalan. Opsi \texttt{-e trace=network}
membatasi output hanya ke system call terkait jaringan. Opsi \texttt{-c} merangkum
frekuensi dan durasi setiap system call, berguna untuk profiling.

\begin{warningbox}
\cmd{strace} menghasilkan output yang sangat banyak dan memperlambat proses target
secara signifikan (hingga 10--100x). Jangan gunakan pada server produksi yang sedang
melayani traffic tinggi. Gunakan dengan \texttt{-e trace=} untuk memfilter hanya
system call yang relevan.
\end{warningbox}

%%: Praktikum ---
\subsection*{Praktikum 11.5: Pemantauan Aplikasi}
\textbf{Tujuan:} menggunakan berbagai alat pemantauan untuk mengidentifikasi
penggunaan sumber daya, file yang terbuka, port yang digunakan, dan dependensi
library dari aplikasi yang berjalan.

\textbf{Langkah-langkah:}
\begin{enumerate}
    \item Jalankan sebuah aplikasi untuk dipantau (web server nginx dalam container):
\begin{lstlisting}[language=bash, caption={Menyiapkan aplikasi untuk dipantau}]
sudo apt install nginx -y
sudo systemctl start nginx
sudo systemctl status nginx
pgrep -a nginx
\end{lstlisting}

    \item Pantau penggunaan sumber daya nginx:
\begin{lstlisting}[language=bash, caption={Memantau penggunaan CPU dan memori}]
ps aux | grep nginx
ps -eo pid,user,cmd,%mem,%cpu | grep nginx
top -b -n 1 | grep nginx
\end{lstlisting}

    \item Periksa port yang digunakan dan file yang terbuka:
\begin{lstlisting}[language=bash, caption={Memeriksa port dan file terbuka}]
ss -tlnp | grep nginx
sudo lsof -p $(pgrep nginx | head -1) | head -20
sudo lsof -i :80
sudo lsof /var/log/nginx/access.log
\end{lstlisting}

    \item Periksa dependensi library nginx:
\begin{lstlisting}[language=bash, caption={Memeriksa dependensi library}]
which nginx
ldd $(which nginx)
ldd $(which nginx) | wc -l
apt-cache depends nginx | head -10
\end{lstlisting}

    \item Gunakan strace untuk melihat apa yang dilakukan nginx saat menerima
        request (jalankan di terminal terpisah):
\begin{lstlisting}[language=bash, caption={Analisis system call dengan strace}]
sudo strace -p $(pgrep nginx | head -1) -e trace=network -c &
STRACE_PID=$!
curl -s http://localhost > /dev/null
sleep 2
sudo kill $STRACE_PID 2>/dev/null
\end{lstlisting}

    \item Bersihkan setelah praktikum:
\begin{lstlisting}[language=bash, caption={Membersihkan setelah praktikum}]
sudo systemctl stop nginx
sudo apt purge nginx -y
sudo apt autoremove -y
\end{lstlisting}
\end{enumerate}

\begin{exercisebox}[11.5]
\begin{enumerate}
    \item Dari output \cmd{lsof -p \$(pgrep nginx | head -1)}, identifikasi tiga
        jenis berbeda dari file yang dibuka (gunakan kolom \texttt{TYPE}): file
        reguler, direktori, dan socket. Apa fungsi masing-masing?
    \item Mengapa \cmd{ps aux} menampilkan beberapa proses nginx (bukan satu)?
        Apa peran masing-masing proses tersebut? (Petunjuk: lihat perbedaan nama
        pengguna di kolom USER.)
    \item Jalankan \cmd{ldd \$(which ls)} dan hitung berapa library yang
        dibutuhkan oleh perintah \cmd{ls} yang sederhana. Mengapa binary yang
        tampaknya sederhana membutuhkan banyak library?
\end{enumerate}
\end{exercisebox}

\section{Rangkuman}
\label{sec:appmanagement-summary}
%% ========================================================================

Bab ini telah membahas lima topik utama manajemen aplikasi di Linux:

\begin{description}
    \item[Sistem Manajemen Paket] Arsitektur dua lapisan Debian/Ubuntu: \cmd{dpkg}
        sebagai alat tingkat rendah dan \cmd{apt} sebagai alat tingkat tinggi yang
        mengelola dependensi otomatis. Perintah kunci: \cmd{apt update}, \cmd{apt
        install}, \cmd{apt purge}, \cmd{dpkg -L}, \cmd{dpkg -S}.

    \item[Manajemen Repositori] Konfigurasi sumber paket melalui \\
        \file{/etc/apt/sources.list} dan \dir{/etc/apt/sources.list.d}. \\
        Penambahan repositori pihak ketiga yang aman menggunakan metode \\
        \texttt{signed-by} dengan GPG key tersendiri.

    \item[Kompilasi dari Source] Pola tiga langkah autotools: \cmd{./configure},
        \cmd{make}, \cmd{make install}. Penggunaan \cmd{checkinstall} untuk membungkus
        hasil kompilasi menjadi paket dpkg yang terkelola. Pola CMake dengan
        out-of-source build.

    \item[Container Docker] Konsep image, container, Dockerfile, dan Docker Compose.
        Dockerfile mendefinisikan cara membangun image; Docker Compose
        mendefinisikan cara menjalankan stack multi-container secara deklaratif
        melalui \file{docker-compose.yml}. Perintah kunci: \cmd{docker pull},
        \cmd{docker run}, \cmd{docker build}, \cmd{docker exec}, \cmd{docker
        compose up}, \cmd{docker compose down}. Container berbagi kernel host
        sehingga lebih ringan dari VM tetapi dengan isolasi yang lebih lemah.

    \item[Pemantauan Aplikasi] Alat diagnostik: \cmd{ps}/\cmd{top}/\cmd{htop} untuk
        pemantauan proses, \cmd{lsof} untuk file dan socket yang terbuka, \cmd{ss}
        untuk status koneksi jaringan, \cmd{ldd} untuk dependensi library, dan
        \cmd{strace} untuk analisis system call mendalam.
\end{description}

\section{Latihan}
\label{sec:appmanagement-exercises}

\begin{exercisebox}[Latihan 11.A: Audit Software Server]
Lakukan audit lengkap software yang terinstall di sistem Ubuntu Server:
\begin{enumerate}
    \item Tampilkan jumlah total paket yang terinstall dan buat daftar 20 paket
        terbesar berdasarkan ukuran disk yang digunakan (\cmd{dpkg-query -Wf}
        dengan format \texttt{\$\{Installed-Size\}\textbackslash{}t\$\{Package\}}).
    \item Identifikasi paket-paket yang memiliki status \texttt{rc} (dihapus tapi
        konfigurasi masih ada) dan hapus konfigurasi yang tersisa menggunakan
        \cmd{apt purge}.
    \item Periksa apakah ada pembaruan keamanan yang belum diinstall menggunakan
        \cmd{apt list --upgradable} dan filter hanya pembaruan dari
        \texttt{-security}.
\end{enumerate}
\end{exercisebox}

\begin{exercisebox}[Latihan 11.B: Containerisasi Aplikasi Web]
Buat setup container untuk melayani aplikasi web statis:
\begin{enumerate}
    \item Buat Dockerfile yang menggunakan \texttt{nginx:alpine} sebagai base image
        dan menyalin direktori berisi minimal 3 file HTML ke dalam image.
    \item Build image dengan tag yang bermakna (\texttt{nama-app:versi}).
    \item Jalankan container dengan port forwarding ke port 8080.
    \item Verifikasi semua halaman dapat diakses menggunakan \cmd{curl}.
    \item Periksa ukuran image yang dihasilkan (\cmd{docker images}) dan bandingkan
        dengan image dasar \texttt{nginx:alpine}.
\end{enumerate}
\end{exercisebox}

\begin{exercisebox}[Latihan 11.C: Pemecahan Masalah Aplikasi]
Seorang administrator melaporkan bahwa web server tidak bisa distart karena
``port sudah digunakan''. Selesaikan skenario berikut:
\begin{enumerate}
    \item Gunakan \cmd{ss -tlnp} untuk mengidentifikasi proses mana yang menggunakan
        port 80 dan/atau 443.
    \item Gunakan \cmd{ps aux} dan \cmd{lsof -i :80} untuk mendapatkan informasi
        lengkap tentang proses tersebut.
    \item Jelaskan langkah-langkah yang akan Anda ambil untuk memutuskan apakah
        proses tersebut harus dihentikan atau dikonfigurasi ulang agar tidak konflik.
    \item Tulis skrip bash sederhana yang memeriksa apakah port 80 sudah digunakan
        sebelum mencoba start nginx, dan menampilkan pesan yang informatif jika port
        sudah terpakai.
\end{enumerate}
\end{exercisebox}
